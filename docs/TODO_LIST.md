## 에이전트 규칙

1. **시작 전에 읽는다.** 맡은 일이 어느 항목(ID)인지 찾는다. 목록에 없는 일이면 **먼저 항목을 추가하고** 시작한다
2. **순서.** 요청서가 붙은 항목(`[16]`~`[21]`)은 [요청서 목차](features/requests/README.md)의 순서와 선행 관계를 따른다.
   요청서가 없는 항목은 **요청자가 고른 것만** 한다 — 에이전트가 임의로 집어 들지 않는다
3. **❓ 가 붙은 항목은 요청자 결정이 먼저다.** 결정을 받기 전에는 구현하지 않는다
4. **줄 긋는 시점.** `qa-master` 가 "QA 통과" 라고 확인한 뒤에만 긋는다 (`CLAUDE.md` 워크플로 6번).
   코드가 없는 항목(문서·요청자 할 일)은 결과를 확인했을 때 긋는다. 줄 긋기는 **그 작업의 커밋에 함께** 넣는다
5. **줄 긋는 형식.** 체크하고, 줄을 긋고, 뒤에 날짜와 근거를 붙인다. **줄을 지우지 않는다** (기록이다)
   ```
   - [x] ~~**INQ-1** 문의 7개 오퍼레이션을 서버에 만든다~~ — 완료 2026-10-25 · 요청서 16
   ```
6. **일부만 끝났으면 긋지 않는다.** 항목을 둘로 나눠 끝난 쪽만 긋고, 남은 쪽은 새 ID 로 남긴다
7. **새로 발견한 것**(버그, 미룬 것, 계약과 구현의 격차)은 해당 화면 절 끝에 **다음 번호**로 추가하고 근거를 붙인다.
   `known-issues.md`·화면 문서 갱신 규칙은 그대로다 — 이 파일은 그 문서들을 대신하지 않는다
8. **[만들지 않기로 한 것](#만들지-않기로-한-것--todo-아님)** 에 있는 것은 요청자가 다시 정하기 전에는 만들지 않는다
