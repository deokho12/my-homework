# 관리자 — 문의

> 환자가 병원 상세의 `문의하기`로 남긴 질문을 보고 **답변을 한 번 등록하는** 화면입니다. 왼쪽이 목록, 오른쪽이 상세 + 답변 작성칸입니다.

| | |
|---|---|
| **주소** | `/admin/inquiries` (문의를 고르면 `/admin/inquiries/:id`) |
| **누가 보나요** | 병원 담당자(`hospital_admin`)는 **지금 고른 담당 병원의 문의만**, 운영자(`operator`)는 전체를 **보기만** 합니다 |
| **어디서 들어오나요** | 관리자 메뉴의 `문의`(옆 숫자 = 미답변 수), 대시보드의 `답변 안 한 문의` 카드·`오늘 할 일` |
| **소스 파일** | `frontend/src/pages/admin/AdminInquiriesPage.tsx` (목록·상세는 `frontend/src/features/inquiry/components/`, 자주 쓰는 답변 문구는 `frontend/src/features/inquiry/content/answerTemplates.ts`) |

## 여기서 할 수 있는 일

상태 표시: ✅ 실제로 동작함 · 🟡 화면은 되지만 데이터가 샘플 · 🚧 아직 아무 일도 안 일어남 · 🔒 로그인 필요

| 할 수 있는 일 | 상태 | 지금 어떻게 동작하나요 |
|---|---|---|
| 상태 탭 바꾸기 | ✅ 🔒 | `미답변 N` · `답변완료 N` · `전체 N`. 숫자는 **지금 고른 담당 병원**의 현황이고, 탭을 바꾸면 주소에 `?status=answered` 처럼 남습니다 (기본 탭은 주소에 적지 않습니다). 키보드 ←/→/Home/End 로도 옮길 수 있습니다 |
| 목록에서 문의 고르기 | ✅ 🔒 | 고르면 오른쪽에 상세가 열립니다 (좁은 화면에서는 목록 대신 상세가 보이고, 뒤로 가기로 목록에 돌아옵니다) |
| `자주 쓰는 답변` 넣기 | ✅ 🔒 | `진료시간 안내` `비용 안내` `상담 예약 권유` 세 개. 누르면 답변칸을 그 문구로 **덮어씁니다.** 이미 쓴 글이 있으면 먼저 물어봅니다 |
| 답변 쓰기 | ✅ 🔒 | 5자 이상 1000자 이하. `[진료시간]` 처럼 대괄호가 남아 있으면 그 자리를 짚어 알려줍니다 |
| 공개 여부 고르기 | ✅ 🔒 | `다른 환자에게도 공개 (병원 상세 문의)` 체크박스. **환자가 공개를 원한 문의면 기본으로 켜져 있습니다** |
| 답변 등록 | ✅ 🔒 | 상세가 답변 완료 모습으로 바뀌고 `답변을 등록했어요. 환자에게 알림이 갔어요.` 가 뜹니다. 그 문의는 `답변완료` 로 옮겨가고 탭 숫자도 함께 바뀝니다 |
| 답변 수정·삭제 | 🚧 | **없습니다.** 한 번 등록하면 끝입니다 (아래 "알아두실 것") |

## 화면에 보이는 정보

- **제목** — `문의` + `환자가 병원 상세에서 '문의하기'로 남긴 질문이에요. 답변하면 환자에게 알림이 갑니다.`
- **상태 탭 3개** — 숫자는 **담당 병원 전체**의 현황입니다 (지금 보고 있는 목록 길이가 아니라 전체 합계)
- **왼쪽 목록 항목** — 상태 칩(`미답변`/`답변완료`) · 접수 시각(`10/7 18:20`) · 질문 첫 줄 · `김*준 · 가격`
- **오른쪽 상세** — `김*준 · 가격 · 10/7 18:20` · 질문 제목(첫 줄) · 질문 전문 · (환자가 비공개면) `환자가 비공개로 요청함` 배지
- **답변 영역** (미답변일 때) — 자주 쓰는 답변 3개 · 답변칸 · 의료광고 주의 문구 · 공개 체크박스 · `답변 등록`
- **답변 블록** (답변완료일 때) — `○○치과 답변 · 공개` 또는 `· 비공개` + 답변 전문 + 등록 시각

### 특별한 상황일 때

| 상황 | 화면 |
|---|---|
| 아직 문의를 고르지 않음 (넓은 화면) | 오른쪽에 `왼쪽에서 문의를 선택하세요` |
| 미답변이 하나도 없음 | `답변할 문의가 없어요` (답변완료 탭은 `아직 답변한 문의가 없어요`, 전체 탭은 `아직 도착한 문의가 없어요`) |
| 담당하지 않는 병원의 문의 주소로 들어옴 | `문의를 찾을 수 없어요` — **"권한이 없다"고 말하지 않습니다.** 그렇게 말하면 주소를 바꿔가며 "저 병원에 비공개 문의가 몇 건 있다"를 알아낼 수 있기 때문입니다 |
| 쓰던 답변이 있는 채로 다른 문의를 고름 | `작성 중인 답변이 있어요 / 저장하지 않고 다른 문의를 열까요?` 를 물어봅니다 |
| 대괄호가 남은 채 `답변 등록` | `대괄호가 그대로예요 / [진료시간] 부분이 남아 있어요. 이대로 등록할까요?` — **막지는 않고 한 번 더 묻습니다** |
| 등록에 실패함 | 브라우저 알림창으로 `답변을 등록하지 못했어요` + 이유. **쓴 답변은 그대로 남습니다** |
| 운영자 계정으로 봄 | 문의는 **전 병원**이 보이지만, 답변칸 대신 `답변은 병원 담당자만 할 수 있어요` 가 보입니다 |

## 알아두실 것

- **답변은 한 번만 등록할 수 있고 고칠 수 없습니다.** 공개 Q/A 는 환자가 읽는 글이고, `문의에 답변이 왔어요` 알림을 받고 본 내용이 나중에 조용히 바뀌면 그 알림이 거짓이 됩니다. 수정이 필요해지면 답변 이력과 함께 따로 설계합니다.
- **운영자는 답변할 수 없습니다.** 답변은 그 병원의 진료시간·가격을 말하는 행위라, 운영자가 대신 답하면 병원이 하지 않은 말이 병원 이름으로 남습니다.
- **문의자 이름은 누구에게나 `김*준` 처럼 가려집니다.** 담당 병원 관리자에게도 마찬가지이고, 전화번호는 아예 저장되지 않습니다. 문의는 연락처 없이 앱 안에서 답하는 창구이기 때문입니다.
- **공개로 답해도 환자가 비공개로 물었으면 공개되지 않습니다.** 둘 다 공개여야 병원 상세에 올라갑니다. 환자가 비공개로 물었으면 체크박스 대신 `환자가 비공개로 남긴 문의예요. 답변도 환자에게만 보여요.` 가 보입니다.
- **탭의 `답변완료 N` 과 병원 상세의 `답변 N` 은 다른 숫자입니다.** 전자는 답변한 모든 문의, 후자는 **공개로 보이는 Q/A** 만 셉니다.
- **등록해도 실제로 환자에게 문자·전화가 가지 않습니다.** 서버가 없어서 앱 안 알림함에만 쌓이고, 그 알림도 이 브라우저 안에만 있습니다.
- **목록은 100건까지만 받아옵니다.** 그 이상 쌓이면 101번째부터 화면에서 조용히 빠집니다 (탭 숫자는 전체를 셉니다). 페이지 넘기는 UI 가 아직 없습니다.
- **읽음 표시가 없습니다.** 배지와 탭의 `미답변 N` 은 "안 읽은 수" 가 아니라 **답하지 않은 수**입니다. 담당자가 여럿일 때 누구 기준으로 읽음을 셀지 정하지 않아서 그렇게 두었습니다.
- **병원별로 좁혀 보는 필터가 화면에 없습니다.** 담당 병원이 여러 곳이면 모두 섞여서 한 목록에 나옵니다 (항목마다 병원 이름이 따로 보이지는 않습니다).

## 이 화면을 바꾸고 싶을 때

`docs/features/requests/_TEMPLATE.md` 를 복사해서 `docs/features/requests/` 에 요청서를 만들거나,
채팅창에 `/feature-request` 를 입력하세요.

이 화면에서 손대면 함께 확인해야 하는 것:

- 여기서 등록한 답변은 **사용자 쪽 세 곳**에 동시에 나타납니다: 마이페이지 `내 문의`([mypage.md](mypage.md)), 공개로 답했다면 병원 상세의 `문의` 섹션([hospital-detail.md](hospital-detail.md)), 그리고 알림함([notifications.md](notifications.md)).
- **탭 숫자와 관리자 홈의 `문의 N` 은 같은 요약 응답을 씁니다.** 한쪽만 다른 계산으로 바꾸면 두 화면의 숫자가 어긋납니다.
- **공개/비공개 표기는 공개 판정 함수 하나**(`frontend/src/features/inquiry/inquiryVisibility.ts`)에서 나옵니다. 병원 상세의 노출 조건과 같은 함수입니다.
- `자주 쓰는 답변` 문구는 **서버가 모르는 클라이언트 장치**입니다. 문구를 고쳐도 서버 계약은 바뀌지 않습니다.
