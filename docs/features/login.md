# 로그인

> 이미 가입한 계정으로 로그인하는 화면입니다. 찜하기·상담 신청처럼 로그인이 필요한 기능을 누르면 여기로 오게 됩니다.

| | |
|---|---|
| **주소** | `/auth/login` (돌아갈 화면이 있을 때는 `/auth/login?redirect=/consult/h1` 처럼 주소 뒤에 붙습니다) |
| **누가 보나요** | 로그인하지 않은 사용자 |
| **어디서 들어오나요** | 마이페이지의 `로그인` 버튼, 넓은 화면 상단의 `로그인 및 회원가입` 버튼, 그리고 비로그인 상태로 찜하기·상담 신청을 눌렀을 때 자동으로 |
| **소스 파일** | `frontend/src/screens/auth/login.tsx` (화면) + `frontend/src/store/useAuthStore.ts` (계정 확인·저장) |

## 여기서 할 수 있는 일

상태 표시: ✅ 실제로 동작함 · 🟡 화면은 되지만 데이터가 샘플 · 🚧 아직 아무 일도 안 일어남 · 🔒 로그인 필요

| 할 수 있는 일 | 상태 | 지금 어떻게 동작하나요 |
|---|---|---|
| 이메일 입력 | ✅ | 자유롭게 입력합니다. 형식은 검사하지 않습니다 |
| 비밀번호 입력 | ✅ | 입력한 글자가 점(●)으로 가려집니다 |
| 로그인 | ✅ | 이 브라우저에 저장된 계정 목록에서 이메일을 찾아 비밀번호가 같은지 확인합니다. 맞으면 바로 로그인되고, 틀리면 빨간 글씨로 안내가 뜹니다 |
| 로그인 후 원래 하려던 일로 돌아가기 | ✅ | 찜하기·상담 신청 때문에 넘어온 경우, 로그인하면 그 화면으로 돌아갑니다. 그냥 들어온 경우에는 직전 화면으로 돌아갑니다 |
| 회원가입 화면으로 가기 | ✅ | 아래쪽 `아직 계정이 없으신가요? 회원가입` |
| 구글로 계속하기 | 🚧 | 누르면 알림창으로 `준비중이에요` / `구글 로그인은 다음 업데이트에서 지원할 예정이에요.` 만 뜹니다. 실제 로그인은 되지 않습니다 |
| 카카오로 계속하기 | 🚧 | 위와 같습니다 (`카카오 로그인은 다음 업데이트에서 지원할 예정이에요.`) |
| 뒤로 가기 | ✅ | 화면 위쪽 `‹` 화살표 |

## 화면에 보이는 정보

- **화면 제목** — 헤더에 `로그인`, 본문에도 큰 글씨로 `로그인`
- **안내 문구** — `로그인하고 찜한 병원과 상담 신청 내역을 관리해보세요`
- **이메일 / 비밀번호 입력 칸**
- **빨간 오류 문구** — 로그인에 실패했을 때만, 비밀번호 칸과 `로그인` 버튼 사이에 한 줄로 나타납니다
- **`로그인` 버튼** — 조건을 채우기 전에는 흐리게 보이고 눌리지 않습니다
- **회원가입 안내 줄** — `아직 계정이 없으신가요? 회원가입`
- **`간편 로그인 (준비중)` 구분선** + `구글로 계속하기` `카카오로 계속하기` 버튼

### 입력 칸별로 지금 무엇을 검사하나요

| 입력 칸 | 안내 문구(placeholder) | 지금 실제로 검사하는 것 | 검사하지 않는 것 |
|---|---|---|---|
| 이메일 | `example@email.com` | 앞뒤 공백을 뺀 뒤 한 글자 이상인지 | **이메일 형식을 검사하지 않습니다.** `@` 가 없어도, `abc` 여도 버튼은 켜집니다 (다만 그런 계정은 없으니 로그인은 실패합니다) |
| 비밀번호 | `비밀번호` | 한 글자 이상인지 | 길이·복잡도 확인 없음. **공백 한 칸도 한 글자로 인정되어 버튼이 켜집니다** |

즉 **`로그인` 버튼이 켜지는 조건은 "두 칸이 비어있지 않은 것" 뿐입니다.** 맞는 계정인지는 버튼을 누른 뒤에 확인합니다.

### 로그인에 실패했을 때

| 상황 | 나오는 문구 |
|---|---|
| 가입하지 않은 이메일 | `이메일 또는 비밀번호가 올바르지 않아요` |
| 비밀번호가 틀림 | `이메일 또는 비밀번호가 올바르지 않아요` (위와 **똑같은 문구**입니다) |

- 이 문구는 입력 칸 바로 아래가 아니라 **`로그인` 버튼 바로 위**에 한 줄로 나옵니다. 그래서 이메일이 문제인지 비밀번호가 문제인지 구분되지 않습니다.
- 이메일이나 비밀번호를 한 글자라도 고치면 문구가 즉시 사라집니다.

### 이메일·비밀번호를 비교하는 방식

- 이메일은 **앞뒤 공백을 지우고 모두 소문자로 바꿔서** 비교합니다. `Hong@Test.com` 과 `hong@test.com` 은 같은 계정입니다.
- 비밀번호는 **입력한 그대로** 비교합니다. 대소문자가 다르거나 공백이 섞이면 다른 비밀번호로 봅니다.

|---|---|

| 로그인하기 전에 있던 화면 / 하려던 화면 | 로그인 성공 |
| 직전 화면 | 헤더의 `‹` |

## 알아두실 것

- **서버가 없어서 브라우저 안에서만 동작합니다.** 계정은 이 브라우저에만 저장되므로, **회원가입한 브라우저에서만 로그인할 수 있습니다.** 다른 컴퓨터, 다른 브라우저, 시크릿 창에서는 같은 이메일로 로그인해도 `이메일 또는 비밀번호가 올바르지 않아요` 가 나옵니다. 브라우저 데이터를 지우면 계정도 함께 사라집니다.
- **비밀번호가 브라우저에 그대로 저장됩니다.** 암호화하지 않은 임시 구현이라 실제 서비스로 쓸 수 없습니다. **평소 쓰시는 실제 비밀번호는 절대 입력하지 마세요.**
- **비밀번호 찾기·재설정 기능이 없습니다.** 비밀번호를 잊으면 다른 이메일로 새로 가입해야 합니다.
- **구글·카카오 로그인은 버튼만 있습니다.** 누르면 `준비중이에요` 알림창만 뜹니다.
- **오류 안내가 어느 칸의 문제인지 알려주지 않습니다.** 두 경우 모두 같은 문구가 버튼 위에 나옵니다.
- **이메일 형식을 검사하지 않습니다.** `@` 없이도 버튼이 켜집니다.
- **한 번 로그인하면 계속 유지됩니다.** 새로고침해도 로그인 상태가 남고, 자동 만료도 없습니다. 로그아웃은 마이페이지의 `로그아웃` 버튼에서 합니다.
- **입력 칸에서 Enter 를 눌러도 로그인되지 않습니다.** `로그인` 버튼을 눌러야 합니다.
- 주소를 직접 입력해 이 화면에 들어온 뒤 로그인하면, 돌아갈 직전 화면이 없어 브라우저가 이전 페이지(사이트 밖)로 나갈 수 있습니다. **(확인 필요 — 실제 브라우저에서 확인하지 못했습니다)**
- 넓은 화면(PC)에서는 위쪽에 상단 메뉴 바와 `로그인` 헤더가 함께 보입니다.

## 이 화면을 바꾸고 싶을 때

`docs/features/requests/_TEMPLATE.md` 를 복사해서 `docs/features/requests/` 에 요청서를 만들거나,
채팅창에 `/feature-request` 를 입력하세요.

이 화면에서 손대면 함께 확인해야 하는 것:

- **회원가입 화면과 같은 계정 저장소**를 씁니다. 한쪽의 이메일 처리 방식을 바꾸면 다른 쪽도 함께 바꿔야 로그인이 됩니다.
- **로그인 상태는 앱 전체가 함께 봅니다.** 찜하기, 상담 신청, 마이페이지, 상단 메뉴의 로그인 버튼 표시가 모두 이 상태에 따라 달라집니다.
- **"로그인 후 원래 자리로 돌아가기"** 는 이 화면으로 보내는 쪽(병원 상세의 찜하기·상담 신청 등)이 넘겨준 주소로 동작합니다. 돌아가는 동작을 바꾸려면 보내는 쪽도 함께 확인해야 합니다.
