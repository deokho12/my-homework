# 로그인

> 이미 가입한 계정으로 로그인하는 화면입니다. 찜하기·상담 신청처럼 로그인이 필요한 기능을 누르면 여기로 오게 됩니다.

| | |
|---|---|
| **주소** | `/auth/login` (돌아갈 화면이 있을 때는 `/auth/login?redirect=/consult/h1` 처럼 주소 뒤에 붙습니다) |
| **누가 보나요** | 로그인하지 않은 사용자 |
| **어디서 들어오나요** | 마이페이지의 `로그인` 버튼, 넓은 화면 상단의 `로그인 및 회원가입` 버튼, 그리고 비로그인 상태로 찜하기·상담 신청을 눌렀을 때 자동으로 |
| **소스 파일** | `frontend/src/screens/auth/login.tsx` (화면) + `frontend/src/features/auth/schemas/authSchemas.ts` (입력 검사) + `frontend/src/store/useAuthStore.ts` (로그인 상태) — 계정 확인은 **서버**가 합니다 |

## 여기서 할 수 있는 일

상태 표시: ✅ 실제로 동작함 · 🟡 화면은 되지만 데이터가 샘플 · 🚧 아직 아무 일도 안 일어남 · 🔒 로그인 필요

| 할 수 있는 일 | 상태 | 지금 어떻게 동작하나요 |
|---|---|---|
| 이메일 입력 | ✅ | `로그인` 을 누를 때 이메일 형식인지 검사합니다 (`@` 가 없으면 칸 아래에 `이메일 형식이 올바르지 않아요`) |
| 비밀번호 입력 | ✅ | 입력한 글자가 점(●)으로 가려집니다 |
| 로그인 | ✅ | **서버에 있는 계정**으로 확인합니다. 맞으면 바로 로그인되고, 틀리면 빨간 글씨로 안내가 뜹니다. 어느 컴퓨터·브라우저에서나 같은 계정으로 로그인할 수 있습니다 |
| 로그인 후 원래 하려던 일로 돌아가기 | ✅ | 찜하기·상담 신청 때문에 넘어온 경우, 로그인하면 그 화면으로 돌아갑니다. 그냥 들어온 경우에는 직전 화면으로 돌아갑니다 |
| 회원가입 화면으로 가기 | ✅ | 아래쪽 `아직 계정이 없으신가요? 회원가입` |
| 구글로 계속하기 | 🚧 | 누르면 알림창으로 `준비중이에요` / `구글 로그인은 다음 업데이트에서 지원할 예정이에요.` 만 뜹니다. 실제 로그인은 되지 않습니다 |
| 카카오로 계속하기 | 🚧 | 위와 같습니다 (`카카오 로그인은 다음 업데이트에서 지원할 예정이에요.`) |
| 뒤로 가기 | ✅ | 화면 위쪽 `‹` 화살표 |

## 화면에 보이는 정보

- **화면 제목** — 헤더에 `로그인`, 본문에도 큰 글씨로 `로그인`
- **안내 문구** — `로그인하고 찜한 병원과 상담 신청 내역을 관리해보세요`
- **이메일 / 비밀번호 입력 칸**
- **빨간 오류 문구** — 두 군데에 나옵니다. 입력이 잘못되면 **그 칸 바로 아래**에, 계정이 맞지 않는 것처럼 어느 칸의 문제도 아니면 비밀번호 칸과 `로그인` 버튼 사이에 한 줄로
- **`로그인` 버튼** — 언제나 누를 수 있습니다. 누르는 순간 입력을 검사하고, 문제가 있으면 칸 아래에 알려 줍니다. 서버에 확인하는 동안에는 `로그인 중` 으로 바뀌고 흐려집니다
- **회원가입 안내 줄** — `아직 계정이 없으신가요? 회원가입`
- **`간편 로그인 (준비중)` 구분선** + `구글로 계속하기` `카카오로 계속하기` 버튼

### 입력 칸별로 지금 무엇을 검사하나요

| 입력 칸 | 안내 문구(placeholder) | 지금 실제로 검사하는 것 | 검사하지 않는 것 |
|---|---|---|---|
| 이메일 | `example@email.com` | 비어 있지 않은지(`이메일을 입력해주세요`), **이메일 형식인지**(`이메일 형식이 올바르지 않아요`), 254자 이하인지 | — |
| 비밀번호 | `비밀번호` | 비어 있지 않은지(`비밀번호를 입력해주세요`), 128자 이하인지 | 길이·복잡도 확인 없음 (가입할 때의 6자 규칙은 로그인에서 다시 보지 않습니다) |

검사는 **`로그인` 을 누를 때** 합니다. 한 번 누른 뒤에는 칸을 고치는 대로 다시 검사해서, 고쳐지면 칸 아래 문구가 사라집니다. 맞는 계정인지는 그다음 서버가 확인합니다.

### 로그인에 실패했을 때

| 상황 | 나오는 문구 |
|---|---|
| 가입하지 않은 이메일 | `이메일 또는 비밀번호가 올바르지 않아요` |
| 비밀번호가 틀림 | `이메일 또는 비밀번호가 올바르지 않아요` (위와 **똑같은 문구**입니다) |
| 짧은 시간에 너무 여러 번 시도함 | `요청이 너무 많아요. 잠시 후 다시 시도해주세요` (같은 곳에서 1분에 10번이 넘으면) |

- 이 문구들은 **`로그인` 버튼 바로 위**에 한 줄로 나옵니다. 가입하지 않은 이메일과 틀린 비밀번호를 **일부러 같은 문구**로 보여줍니다 — 다르게 알려 주면 "이 이메일로 가입한 사람이 있다" 가 밖으로 새기 때문입니다.
- 이 문구는 다시 `로그인` 을 누를 때 지워집니다.

### 이메일·비밀번호를 비교하는 방식

- 이메일은 서버가 **앞뒤 공백을 지우고 모두 소문자로 바꿔서** 비교합니다. `Hong@Test.com` 과 `hong@test.com` 은 같은 계정입니다.
- 비밀번호는 **입력한 그대로** 비교합니다. 대소문자가 다르거나 공백이 섞이면 다른 비밀번호로 봅니다.

## 알아두실 것

- **로그인은 실제 서버를 씁니다.** 계정은 서버에 저장되므로 다른 컴퓨터·브라우저·시크릿 창에서도 같은 계정으로 로그인할 수 있습니다. 비밀번호는 서버가 **암호화(복원할 수 없는 형태)** 해서 보관하고, 브라우저에는 비밀번호가 아니라 "로그인했다는 표시"만 남습니다. 예전 임시 구현이 브라우저에 남겨 두었던 비밀번호는 앱이 켜질 때 지웁니다.
- **지금 서버는 개발용입니다.** 개발 서버에는 시험용 계정(일반 사용자·병원 관리자·운영자)이 미리 만들어져 있습니다 — 계정 정보는 개발 쪽에 물어봐 주세요. 실제 서비스 전에는 서버를 운영 환경으로 옮겨야 합니다.
- **비밀번호 찾기·재설정 기능이 없습니다.** 비밀번호를 잊으면 다른 이메일로 새로 가입해야 합니다.
- **구글·카카오 로그인은 버튼만 있습니다.** 누르면 `준비중이에요` 알림창만 뜹니다.
- **계정이 맞지 않을 때는 어느 칸이 틀렸는지 알려주지 않습니다.** 위 "로그인에 실패했을 때" 의 이유 때문입니다. 입력 형식 문제는 그 칸 아래에 알려 줍니다.
- **한 번 로그인하면 유지됩니다.** 새로고침해도 로그인 상태가 남습니다(켜질 때 서버에 로그인 표시가 아직 유효한지 확인합니다). 개발 서버 설정으로는 **최대 30일** 동안 유지되고 그 뒤에는 다시 로그인해야 합니다 **(확인 필요 — 실제로 30일을 기다려 확인하지는 않았습니다)**. 로그아웃은 마이페이지의 `로그아웃` 에서 합니다.
- **입력 칸에서 Enter 를 누르면 `로그인` 을 누른 것과 같습니다.**
- 주소를 직접 입력해 이 화면에 들어온 뒤 로그인하면, 돌아갈 직전 화면이 없어 브라우저가 이전 페이지(사이트 밖)로 나갈 수 있습니다. **(확인 필요 — 실제 브라우저에서 확인하지 못했습니다)**
- 넓은 화면(PC)에서는 위쪽에 상단 메뉴 바와 `로그인` 헤더가 함께 보입니다.

## 이 화면을 바꾸고 싶을 때

`docs/features/requests/_TEMPLATE.md` 를 복사해서 `docs/features/requests/` 에 요청서를 만들거나,
채팅창에 `/feature-request` 를 입력하세요.

이 화면에서 손대면 함께 확인해야 하는 것:

- **회원가입 화면과 같은 계정 저장소**를 씁니다. 한쪽의 이메일 처리 방식을 바꾸면 다른 쪽도 함께 바꿔야 로그인이 됩니다.
- **로그인 상태는 앱 전체가 함께 봅니다.** 찜하기, 상담 신청, 마이페이지, 상단 메뉴의 로그인 버튼 표시가 모두 이 상태에 따라 달라집니다.
- **"로그인 후 원래 자리로 돌아가기"** 는 이 화면으로 보내는 쪽(병원 상세의 찜하기·상담 신청 등)이 넘겨준 주소로 동작합니다. 돌아가는 동작을 바꾸려면 보내는 쪽도 함께 확인해야 합니다.
