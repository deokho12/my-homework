# 혼자 개발 체제로 정리 (서버까지 이 저장소에서 직접 만들기)

**작성자**: 안덕호
**작성일**: 2026-10-21
**대상 화면**: 화면 없음 — 작업 규칙과 문서 (`CLAUDE.md`, `.claude/commands/feature-request.md`, `docs/decisions/0001-roles-and-pii.md`, `docs/api/README.md` §20·§21, `docs/database/README.md` §14·§16, `docs/features/known-issues.md`)
**급한가요**: 급함 — **이것부터.** 13~21 요청서가 이 정리를 전제로 쓰여 있습니다
**먼저 끝나야 하는 요청**: 없음

---

## 무엇을 하고 싶으신가요

협업자가 프로젝트를 떠나서, 앞으로는 제가 혼자 Claude Code 로 개발합니다. 지금까지 "서버는 협업자 영역이라 설계까지만" 하던 방식을 끝내고, **서버까지 이 저장소에서 직접 만들도록** 작업 규칙과 문서를 정리하고 싶어요.

---

## 왜 필요한가요

- 요청서 06·07 이 "협업자 확인 대기" 로 멈춰 있습니다. 확인해 줄 사람이 이제 없습니다
- 상담·문의·찜·알림은 "서버는 협업자 인계" 로 남아 있어 아직 브라우저 안에만 저장됩니다. 실제 환자와 병원이 쓸 수 없는 상태입니다
- 리뷰해 줄 사람이 없으니, 실수를 막는 장치가 규칙에 들어 있어야 합니다

---

## 지금은 어떻게 되어 있나요

- `CLAUDE.md` 에 서버는 `backend-engineer` 라고 되어 있지만, 실제로는 서버 변경을 협업자 영역으로 보고 설계까지만 했습니다
- `/feature-request` 의 구현 단계에는 `frontend-engineer` 만 나오고, "서버가 없는 지금 어디까지 가능한지" 라는 문장이 있습니다
- 결정 문서 0001 의 결정 2 아래에 "변경 제안 (협업자 확인 대기)" 가 있고, 결정 3 은 "미확답" 입니다
- 계약 설명 §20·§21 과 데이터 설계 §14·§16 이 "제안 — 협업자 확인 대기" 입니다
- 작업 브랜치 `feature/screen-plan-2026-10` (요청서 01~10) 은 원격에 올라가 있지만 `main` 은 8월 상태입니다

---

## 이렇게 되면 좋겠어요

1. **작업 규칙** — `CLAUDE.md` 와 `/feature-request` 에 아래 내용을 넣어 주세요
   - 서버도 이 저장소에서 직접 만든다. 협업자 확인을 기다리는 단계는 없다
   - 제품 결정이 필요하면 요청자(안덕호)에게 묻는다. 요청서에 답이 적혀 있으면 그대로 따른다
   - `/feature-request` 5단계에 서버 변경이 있을 때의 순서를 추가한다: `db-master` → `interface-master` → `backend-engineer`. "계약 먼저" 원칙은 그대로 둔다
   - "서버가 없는 지금" 같은 문장은 지금 상태에 맞게 고친다
2. **결정 문서 0001**
   - 결정 2 를 변경 제안대로 고쳐 써 주세요: 직접 가입 + 승인 대기. 2026-10-13 에 제가 확정한 4가지가 그 내용입니다
   - 결정 3 "고객 실명·전화번호는 담당 병원만" 을 **확정**으로 바꿔 주세요
   - 고친 날짜와 이유를 남기고, 예전 문장은 지우지 마세요
3. **"협업자 확인 대기" 표시** — §20·§21·§14·§16 의 표시를 "요청자 답 반영 대기 → 요청서 18·19" 로 바꿔 주세요. 열린 질문의 답은 18·19 요청서에 표로 적어 두었습니다. 실제 반영은 18·19 를 처리할 때 합니다
4. **문서 전체의 "협업자 영역 / 협업자 인계 / 협업자 확인"** — 표현을 찾아서 지금 상태에 맞게 고쳐 주세요. `known-issues.md` 개발자용 메모의 "백엔드 인계" 목록은 요청서 14·15·16 으로 연결해 주세요
5. **요청서** — 남은 일을 12~21 로 다시 썼습니다. 순서와 직접 할 일은 목차 `docs/features/requests/README.md` 에 있습니다. 구 06·07·11 의 상태 줄은 제가 "대체됨" 으로 이미 고쳐 두었습니다. 완료된 요청서(01~05, 08~10)는 그대로 둡니다
6. **브랜치 정리**
   - `feature/screen-plan-2026-10` 을 `main` 에 합치고 push 해 주세요
   - 앞으로는 요청서 하나가 QA 를 통과하면 `main` 에 커밋하고 push 합니다. 혼자라 PR 리뷰 단계는 없습니다
   - 다 끝나면 원격의 `feature/screen-plan-2026-10`·`hospital-doctor-domain-api` 브랜치를 지워도 되는지 확인해서 알려 주세요. 지우는 건 제가 확인한 뒤에 합니다
7. **혼자 개발할 때의 안전장치** — 규칙에 넣어 주세요
   - 커밋 전 완료 게이트(lint · typecheck · test · build)를 **프론트와 백엔드 둘 다** 돌린다
   - 서버 데이터 구조를 바꾸는 작업 전에는 개발 DB(`backend/prisma/dev.db`)를 백업한다
   - 커밋 전에 비밀 키가 들어가지 않았는지 확인한다. `.env` 가 무시되는지, 올라갈 변경에 키처럼 보이는 문자열이 없는지 본다. 저장소가 아직 Public 입니다
