## 무엇을 하고 싶으신가요

환자가 예약 전에 가격·진료시간·주차 같은 궁금한 점을 병원에 연락처 없이 물어보고, 병원은 관리자 화면에서 답하게 하고 싶어요.

---

## 왜 필요한가요

- 상담 신청은 "전화로 연락받기"라 부담이 있습니다. 가벼운 질문 창구가 있어야 상담 신청까지 이어집니다.
- 답변이 빠른 병원이 상담 예약을 더 받게 되는 구조라, 병원에도 동기가 생깁니다.
- 커뮤니티 `질문하기` 는 병원 지정 질문이 아니라 별개입니다.

---

## 지금은 어떻게 되어 있나요

문의 기능은 사용자·관리자 어디에도 없습니다.

---

## 이렇게 되면 좋겠어요

**사용자 — 문의하기 화면 (병원 상세의 `문의하기` 버튼으로 진입)**
- 상단 안내: "연락처 없이 앱 안에서 답변을 받아요. 예약까지 원하시면 상담 신청이 더 빨라요" (`상담 신청` 링크)
- 주제 칩: `가격` `진료시간` `주차·위치` `시술 방법` `기타` (하나 선택)
- 내용 입력칸
- `다른 사람도 볼 수 있게 공개` 체크 (기본 켜짐, 공개해도 닉네임만 보임)
- `문의 남기기` → 완료 화면 ("병원이 답하면 알림으로 알려드릴게요", `내 문의 보기`)
- 로그인 필요

**사용자 — 병원 상세 `문의` 탭**
- 상단 목차(정보 · 시술·가격 · 의료진 · 후기 · 문의)에 `문의` 추가
- `문의 N건 · 답변 N` + `문의하기` 버튼
- **공개 + 답변완료**인 문의만 Q/A 형태로 노출

**병원 관리자 — 문의 화면 (사이드 메뉴 `문의`, 안 읽은 수 배지)**
- 상태 탭: `미답변 N` · `답변완료 N` · `전체 N`
- 왼쪽 목록(상태 칩, 시간, 제목, 닉네임 · 주제), 오른쪽 상세 + 답변 작성
- `자주 쓰는 답변` 버튼 3개(진료시간 안내 / 비용 안내 / 상담 예약 권유)를 누르면 답변칸에 문구가 채워짐
- 답변칸 아래 주의 문구: "치료 효과를 보장하거나, 다른 병원과 비교하거나, 정해지지 않은 할인을 약속하는 표현은 의료광고 규정에 걸릴 수 있어요"
- `답변 등록` → 답변완료로 이동, 환자에게 알림

---

## 이것만은 지켜주세요 / 건드리지 말아주세요

- 이 기능은 **새 데이터(문의)와 새 API**가 필요합니다. AGENTS.md 규칙대로 db-master → interface-master가 스키마와 계약(`docs/api/openapi.yaml`)을 먼저 정하고, 백엔드 구현은 협업자와 확인 후 진행해 주세요. 그 전까지 프론트는 상담·찜과 같은 방식(`lib/localCollection.ts`)으로 먼저 만들어도 됩니다
- 병원 관리자는 **자기 병원 문의만** 봅니다 (`docs/decisions/0001-roles-and-pii.md` 의 역할 규칙)
- 답변 알림은 서버가 만드는 것으로 설계 (상담 알림과 같은 원칙)

---

## 확인하고 싶은 것

- 병원 상세 → `문의하기` → 작성 → 완료 화면이 나온다
- 관리자 문의 화면의 `미답변` 에 방금 문의가 보이고, 사이드 메뉴 배지 숫자가 1 늘었다
- `자주 쓰는 답변` 을 누르면 답변칸이 채워지고, `답변 등록` 하면 `답변완료` 로 넘어간다
- 사용자 알림함에 "문의에 답변이 왔어요" 가 생긴다
- 공개로 남긴 문의는 병원 상세 `문의` 탭에 Q/A로 보이고, 비공개는 보이지 않는다
- 다른 병원 관리자 계정으로는 이 문의가 보이지 않는다

## 검토 결과

- **상태**: 완료 (2026-10-12, QA 통과 — 확인 항목 6개 전부 실제 브라우저에서 확인)
- **영향 범위**:
  - 새 화면: 사용자 `문의하기`(`/inquiry/:hospitalId`), 관리자 `문의`(`/admin/inquiries`, 넓은 화면은 목록+답변 두 칸)
  - 바뀐 화면: 병원 상세(목차 5개 신설 + 영역 재배치 + `문의` 영역), 마이페이지 `내 문의` 탭(실제 데이터, 펼쳐서 답변 읽기), 관리자 홈(`문의 N` 입구), 알림(`문의에 답변이 왔어요` → 내 문의로 이동)
  - 서버 계약(`docs/api/openapi.yaml`): 문의 오퍼레이션 7개·스키마·오류 코드, 알림 종류 `inquiry-answer`. 데이터 구조·권한·마스킹 규칙은 `docs/api/README.md` §3·§4·§9·§14. **서버(협업자 영역)는 손대지 않음** — 서버에 문의 기능이 아직 없어 지금은 브라우저 저장소로 동작
  - 문서: 신규 `inquiry.md`, `admin-inquiries.md` / 갱신 `hospital-detail.md`, `mypage.md`, `admin-home.md`, `notifications.md`, `known-issues.md`, `README.md`
- **판단**:
  - 관리자 문의 입구는 지금은 관리자 홈(사이드 메뉴는 요청서 05). 운영자는 모든 병원 문의를 보지만 답변은 못 하고, 관리자 홈에 숫자도 붙지 않음
  - 공개 Q/A 는 **환자도 공개를 고르고 병원도 답변하며 공개를 허용해야** 병원 상세에 보임. 공개 Q/A 에는 이름이 아예 없음. 관리자에게는 이름이 `김*준` 처럼 가려져 보임(연락처 없는 창구라 원래 이름이 필요 없음)
  - 요청서의 "공개해도 **닉네임**만 보임" 문구는 닉네임이 없고 이름을 싣지 않기로 해서 화면 문구를 "이름은 보이지 않아요" 로 바꿈
  - 문의 제목 칸이 없어 목록 제목은 **내용 첫 줄**. 주제는 처음에 아무것도 안 골라져 있고 하나 골라야 보낼 수 있음
  - 답변 알림을 누르면 **마이페이지 `내 문의` 의 그 문의가 펼쳐진 채** 열림 — 요청서 08 은 "병원 상세 문의로 이동" 이라 적었지만, 비공개 답변은 병원 상세에 없어 읽을 곳이 여기뿐이라 이렇게 정함 (요청서 08 처리 때 재확인 필요)
  - 병원 상세 재배치에서 할인 이벤트 배너는 맨 위에 그대로 둠(상담 신청 전환 영역 유지). 할인 중인 병원은 지금처럼 가격대 대신 배너가 보임
  - 남은 한계(알려진 문제에 기록): 브라우저 저장이라 답변 알림의 앞 60자가 같은 브라우저 다른 계정에도 보임, 병원 상세 공개 Q/A 20건·관리자 목록 100건 상한, 답변 수정·문의 취소·신고·도배 방지 없음
