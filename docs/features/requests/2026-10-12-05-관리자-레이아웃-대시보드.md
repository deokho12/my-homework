# 병원 관리자 화면을 "사이드 메뉴 + 대시보드" 구조로

**작성자**: 안덕호
**작성일**: 2026-10-12
**대상 화면**: 관리자 홈 — `docs/features/admin-home.md` 와 관리자 화면 전체
**급한가요**: 급함 (화면기획 P0)

> 화면기획: https://claude.ai/artifact/BYpaxGQsLrLyYsA7sgqvKV → "병원 관리자" 페이지의 **00 화면 구성**, **02 대시보드**

---

## 무엇을 하고 싶으신가요

병원 관리자가 로그인하면 "오늘 처리할 일"이 먼저 보이고, 왼쪽 메뉴로 상담 예약·문의·병원 정보를 오가게 하고 싶어요.

---

## 왜 필요한가요

지금 `/admin` 은 "병원 프로필 관리" 병원 목록이 첫 화면이라, 매일 하는 일(상담 연락, 문의 답변)이 한 번 더 들어가야 보입니다.

---

## 지금은 어떻게 되어 있나요

- `/admin`: 숫자 2개(이번 달 신규 상담, 처리 대기) + 버튼(상담 관리, 새 병원 등록, 전문의 인증 검수) + 담당 병원 카드 목록
- 각 관리자 화면이 따로 떨어져 있고 공통 메뉴가 없음

---

## 이렇게 되면 좋겠어요

**공통 레이아웃 (관리자 화면 전부)**
- 왼쪽 사이드 메뉴
  - 업무: `대시보드` · `상담 예약`(신규 수 배지) · `문의`(미답변 수 배지)
  - 병원 정보: `기본 정보 · 시술` · `의료진`
  - 홍보 · 확장: `이벤트` `후기` `광고 현황` (`2차` 표시, 아직 비활성) · `기공소 연계` (`준비중` 표시)
  - 맨 아래: 병원명, 이름 · 직책, 승인 상태(`승인 완료 · 앱 노출 중` / `승인 대기`)
- 상단: 화면 제목, 환자 검색(이름·연락처), 알림 종(안 읽은 표시)
- 좁은 화면에서는 메뉴가 위로 쌓임

**대시보드 (`/admin`)**
- 병원 정보 완성도 바: "병원 정보 70% 입력됨 · 남은 항목: 진료시간, 병원 사진 3장 이상, 시술 가격" → 누르면 병원 정보로
- 숫자 카드 4개 (각각 누르면 해당 화면): 오늘 들어온 상담 / 처리 대기(신규+연락중, 24시간 지연 건수) / 답변 안 한 문의 / 이번 달 예약확정(전체 상담 대비)
- 오늘 할 일 목록: 지연 상담, 신규 상담 연락, 미답변 문의, 자격증 반려 재업로드
- 최근 상담 예약 표 (4~5건, `전체 보기`)
- 오늘 내원 예정 (예약확정 + 오늘 일시인 건)
- 이번 달 상담 흐름: 상담 신청 → 연락 완료 → 예약확정 → 내원완료 건수

---

## 이것만은 지켜주세요 / 건드리지 말아주세요

- 권한 가드(`App.tsx` 의 `admin` 가드)는 그대로
- 한 사람이 여러 병원을 담당할 수 있는 구조(`hospital_admins` M:N)는 유지. 담당 병원이 여러 개면 사이드 메뉴 위에 병원 선택 드롭다운을 두고, 1개면 숨김
- 운영자 전용 기능(전문의 인증 검수, 병원 생성)은 운영자에게만 메뉴 노출
- 숫자 중 서버 집계가 필요한 것은 interface-master가 계약을 먼저 정하고 협업자와 확인
- 화면이 바뀌면 `docs/features/admin-*.md` 와 `docs/features/README.md` 도 갱신 (README의 "관리자 화면에 로그인 검사가 없다" 문구는 지금 코드와 다릅니다)

---

## 확인하고 싶은 것

- 병원 관리자로 로그인해 `/admin` 에 오면 대시보드와 사이드 메뉴가 보인다
- 사이드 메뉴로 상담 예약·문의·기본 정보·의료진을 오갈 수 있고 현재 메뉴가 강조된다
- 신규 상담이 생기면 `상담 예약` 배지 숫자와 대시보드 숫자가 같이 늘어난다
- 숫자 카드를 누르면 해당 화면으로 간다
- 일반 사용자로 `/admin` 에 들어가면 막힌다

## 검토 결과

- **상태**: 완료 (2026-10-13, QA 통과 — 확인 항목 5개 + 요청자 숫자 기준 전부 실제 브라우저에서 확인. 1차 QA 에서 나온 결함 2건(좁은 화면 `더보기` 가 접히지 않음, 상단 검색이 `신규`·`최근 30일` 안에서만 찾음)을 고친 뒤 재검증)
- **요청자가 정한 숫자 기준 (2026-10-13)**:
  - 이번 달 예약확정: M = 이번 달 신청된 상담(신청일 기준), N = 그중 지금 상태가 예약확정·내원완료인 건. 문구 예 "이번 달 신청 42건 중 18건 예약"
  - 상담 흐름: 상담 신청 = 이번 달 신청 전체 / 연락 완료 = 그중 신규가 아닌 건(취소 사유가 '연락이 안 됨'인 건 제외) / 예약확정 = 예약확정+내원완료 / 내원완료 = 내원완료
  - 병원 정보 완성도: 지금 입력 가능한 항목만 같은 비중(기본 정보, 진료시간, 시술 1개 이상, 대표 이미지, 병원 소개, 의료진 1명 이상 등). 시술별 가격·사진 업로드는 07 에서 추가. 시술이 0개면 완성도와 별개로 "앱에 노출되지 않아요" 경고. 빠진 항목은 이름으로 보이고 누르면 그 입력 칸으로 이동
  - '지연' 은 상담 예약 목록과 같은 판정 함수(24시간)
  - 숫자 카드는 선택한 담당 병원 기준 (04 에서 남은 한계 해소)
- **영향 범위**:
  - 화면: 관리자 화면 **전부**(대시보드·상담 예약·문의·병원 정보 수정·알림함, 운영자의 검수·병원 등록)가 **왼쪽 메뉴 + 위쪽 상단바** 틀 안으로. 좁은 화면에서는 메뉴가 위쪽 칩 줄 + `더보기` 로 접힘. 환자 앱의 상단바·하단탭은 관리자 화면에서 사라지고 메뉴 아래 `몰라몰라 앱으로` 로 돌아감
  - `/admin` 이 **대시보드**로: 병원 정보 완성도, 숫자 카드 4개, 오늘 할 일, 최근 상담 예약, 오늘 내원 예정, 이번 달 상담 흐름. 운영자는 같은 틀에 병원 목록·검수 대기
  - 메뉴 배지(`신규 N`·`문의 N`)와 숫자 카드가 **한 응답**에서 와서 서로 다른 숫자를 말할 수 없음. 상담 상태를 바꾸면 둘이 함께 바뀜
  - 담당 병원이 2곳 이상이면 메뉴 위 드롭다운으로 고르고, 모든 숫자가 그 병원 기준(요청서 04 에서 남은 한계 해소)
  - 상담 예약 목록이 상태 여러 개를 한 번에 받음(`처리 대기 = 신규 + 연락중`)과 `이번 달` 기간 — 카드를 누르면 그 숫자와 같은 건수의 목록이 열림
  - 병원 정보 수정 화면: 완성도의 빠진 항목·`의료진` 메뉴를 누르면 그 입력 칸으로 이동·강조
  - 서버 계약·데이터 설계(`docs/api/openapi.yaml` 의 `GET /admin/dashboard`, `docs/api/README.md` §14, `docs/database/README.md` §13) 추가. **서버(협업자 영역)는 손대지 않음** — 상담·문의가 아직 서버에 없어 대시보드 집계는 브라우저에서 같은 모양으로 계산. 인계 목록은 데이터 설계 문서 §13
  - 정리: 옛 관리자 홈 숫자(`GET /consult-requests/summary`)는 이제 어느 화면도 쓰지 않아 프런트 코드를 지우고 계약에 "소비 화면 없음" 으로 표시. 계약의 `예약 비율(%)` 필드도 화면이 쓰지 않아 뺌
  - 문서: `admin-shell.md`(신규), `admin-home.md` 전면 갱신, `admin-consultations.md`, `admin-consultation-detail.md`, `admin-hospital-edit.md`, `admin-inquiries.md`, `admin-notifications.md`, `admin-specialists.md`, `README.md`, `known-issues.md`
- **판단**:
  - 숫자는 요청자가 정한 기준 그대로. `지연` 은 상담 예약 목록과 **같은 함수**(24시간)라 두 화면이 갈리지 않음 — QA 에서 같은 2건이 양쪽에 나오고 23시간 건은 양쪽 다 안 나오는 것을 확인
  - `처리 대기` 카드와 `신규 상담 연락하기` 는 **기간과 상관없는** 숫자라, 눌렀을 때 목록도 `전체 기간` 으로 열림(목록 기본값 `최근 30일` 이 오래 밀린 건을 숨기지 않게). QA 에서 35일 지난 신규 건이 목록에 나오는 것 확인
  - `오늘 할 일` 의 지연 건은 신규 건의 일부라, 신규 줄에 `— 그중 N건은 24시간이 지났어요` 로 겹친다고 적음(더해서 읽지 않게)
  - **시술 0개 경고 문구를 바꿈**: 요청의 "앱에 노출되지 않아요" 는 사실과 달라서(시술이 없어도 이름 검색·찜·추천·직접 링크로는 보임) `시술로 찾을 때 병원이 나오지 않아요` + `시술 등록하러 가기`. 참고로 지금 계약은 시술 0개 저장을 막고 있어, 이 경고는 예전 데이터에만 뜸
  - 아직 없는 메뉴(이벤트·후기·광고 현황·기공소 연계)는 전부 회색 `준비중`. `홍보 · 확장` 은 운영자 메뉴에는 두지 않음(병원이 자기 병원을 알리는 기능)
  - 운영자 메뉴 아래 카드는 `운영자 · 모든 병원`. 운영자에게는 대시보드를 부르지 않음
  - 상단바 환자 검색은 **상태·기간과 상관없이** 전체 상담에서 찾음
  - 담당 병원 기본 선택은 마지막으로 고른 병원 → 없으면 담당 목록의 첫 번째(이름순으로 고르려면 목록을 먼저 받아야 해서 첫 화면이 한 번 바뀜). 고른 병원은 이 브라우저에 기억되고 계정이 바뀌면 지워짐
  - 미룬 것(알려진 문제에 근거와 함께 기록): 자격증 반려 **사유**(서버에 관리자용 조회가 없음), `지연` 만 모아 보는 필터, `오늘 내원 예정` 의 `전체 보기`, 완성도의 `시술별 가격`·`병원 사진 3장 이상`(→ 07), 메뉴 아래 직책·승인 상태(→ 06), 깔때기 `연락 완료` 막대의 목록 연결
  - QA 메모: 담당 병원 2곳 전환은 서버에 담당자 지정 기능이 아직 없어(계약만 있음) 로그인 응답을 가공해 확인함. 병원 정보가 덜 채워진 병원도 시드에 없어(11곳 모두 100%) 같은 방식으로 확인
