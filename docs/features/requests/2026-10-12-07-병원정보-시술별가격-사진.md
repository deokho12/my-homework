# 병원 정보 등록 보강 (시술별 가격 · 사진 업로드 · 병원 특징 확장)

**대상 화면**: 병원 정보 수정 — `docs/features/admin-hospital-edit.md`, 병원 상세 — `docs/features/hospital-detail.md`

> 화면기획: https://claude.ai/artifact/BYpaxGQsLrLyYsA7sgqvKV → "병원 관리자" **05 병원 정보 등록**, "사용자 화면" **U5 병원 상세**

---

## 무엇을 하고 싶으신가요

병원이 시술마다 가격(또는 "상담 후 안내")을 적고, 사진을 파일로 올리고, 환자가 병원 상세에서 그걸 시술별로 보게 하고 싶어요.

---

## 왜 필요한가요

환자가 비교하는 건 "이 병원 인레이 얼마?"인데, 지금은 병원 전체 가격대 하나뿐이라 비교가 안 됩니다.

---

## 지금은 어떻게 되어 있나요

`docs/features/admin-hospital-edit.md` 기준: 9개 대분류 펼침 + 세부 시술 체크는 이미 있습니다(세부 31개 중 18개는 `준비중`). 가격은 `가격대 (원) 최소/최대` 하나, 사진은 이미지 URL 입력만, 병원 특징 체크박스 6개입니다.

---

## 이렇게 되면 좋겠어요

- 세부 시술을 체크하면 그 줄에 **가격 입력**: `최소 ~ 최대 만원` 또는 `상담 후 안내` 체크
- 대분류 줄 오른쪽에 `N개 선택 · 앱 노출` (하나도 없으면 `선택 안 함`), 선택된 대분류는 배경색으로 구분
- 시술 섹션 위에 요약: `대분류 N개 노출 · 세부 시술 N개`
- 가격 입력 아래 안내: "비급여 가격은 병원에서 게시한 비급여 진료비용과 다르지 않게 입력해 주세요. 할인 가격은 이벤트에서 따로 등록합니다"
- **사진 파일 업로드**: 대표 1장 + 내부 최대 10장, 대표 표시, 3장 이상 권장
- 병원 특징을 칩으로: 원데이 보철, 디지털 진료(구강스캐너), 야간 진료, 주말 진료, 주차 가능, 수면 진료, 무통 마취, 전담 코디네이터, 장애인 편의시설
  - 18시 이후 진료가 있으면 `야간 진료`, 토·일 진료가 있으면 `주말 진료` 자동 켜짐
- 한 줄 소개(리스트 카드 노출, 40자)
- 상단 섹션 이동 탭: 기본 정보 / 진료 시간 / 사진 / 병원 특징 / 진료 시술·가격
- 하단: `앱 화면 미리보기` + `저장`, 저장 후 "저장됐어요" 안내 (지금은 안내 없이 이전 화면으로 돌아감)
- **사용자 병원 상세**에 `시술·가격` 섹션: 대분류별로 세부 시술과 가격 범위(또는 `상담 후 안내`), 원데이 가능한 시술 옆 `원데이` 표시, 아래 "병원이 등록한 비급여 가격 범위예요. 정확한 비용은 상담으로 확인하세요"

---

## 이것만은 지켜주세요 / 건드리지 말아주세요

- 세부 시술 체크 → 카테고리 노출 규칙(`features/procedure/taxonomy.ts`)은 그대로
- 원데이는 시술이 아니라 병원 특징 (지금과 동일)
- 시술별 가격·사진 파일·특징 확장은 스키마와 계약 변경입니다. db-master → interface-master 순서로 정하고, 백엔드는 협업자와 확인
- 기존 병원 전체 가격대 값은 바로 지우지 말고, 시술별 가격이 없을 때 대신 보여주는 값으로 남겨 두기

---

## 확인하고 싶은 것

- 인레이를 체크하고 가격을 넣어 저장하면, 사용자 병원 상세 `시술·가격` 에 인레이와 그 가격이 보인다
- `상담 후 안내` 를 체크한 시술은 가격 대신 그 문구가 보인다
- 수요일 진료를 21:00까지로 바꾸면 `야간 진료` 가 자동으로 켜진다
- 사진을 파일로 올리면 병원 상세 사진 넘김에 보인다
- 저장하면 "저장됐어요" 안내가 나온다

## 검토 결과

- **상태**: 협업자 확인 대기 (2026-10-13 — 시술별 가격·사진 파일·병원 특징 확장은 전부 서버 데이터 변경이라 **설계까지만** 하고, 서버가 생기면 화면을 만든다. 요청서 06 과 같은 처리)
- **영향 범위** (설계만 — 화면·서버 코드는 아직 바뀌지 않음):
  - 데이터 설계 `docs/database/README.md` §16 (제안): 시술별 가격, 사진, 병원 특징, 한 줄 소개, 대시보드 완성도 7 → 9개
  - 서버 계약 제안 `docs/api/openapi.yaml`(`🚧 [제안]` 표시) + `docs/api/README.md` §21 (열린 질문 12개). **협업자가 합의하기 전에는 확정 계약이 아님**
  - 사진 업로드는 요청서 06 에서 설계한 공용 파일 보관(§14)을 함께 씀 — **06 의 파일 보관이 먼저 만들어져야** 07 의 사진 업로드가 됨
- **판단**:
  - **시술별 가격**은 체크한 시술마다 `최소~최대` 또는 `상담 후 안내`. 저장은 원 단위(화면은 만원으로 보여줌). 지금 서버가 아는 시술 13종에만 붙음 — `준비중` 세부 시술 18개는 지금도 체크할 수 없어 가격도 없음
  - **기존 병원 전체 가격대는 지우지 않음** — 시술별 가격이 하나도 없을 때만 대신 보여줌. 가격이 없는 시술 줄에 전체 가격대를 대신 적지는 않음(그 시술의 가격처럼 보이는 거짓이 됨)
  - **사진**: 대표 1장 + 내부 최대 10장, **맨 앞 사진이 대표**. 대표를 바꾸면 목록 카드 사진도 함께 바뀜(지금은 따로 놀던 문제가 해결됨). 3장 이상은 권장(대시보드 완성도 항목)이고 막지는 않음
  - **병원 특징 칩**: `야간 진료`·`주말 진료`는 **진료시간에서 자동으로** 켜짐(따로 저장하지 않음 — 진료시간을 고쳤는데 칩이 안 바뀌는 일이 없게). 진료시간이 글자로 적혀 있어 읽지 못하면 `야간 진료`는 꺼진 채로 둠(거짓 광고 방지)
  - **한 줄 소개**는 40자, 넘으면 잘라내지 않고 저장을 막음
  - `앱 화면 미리보기`·저장 후 "저장됐어요" 안내·섹션 이동 탭은 데이터 변경이 필요 없음 — 서버가 생기면 화면 작업으로 함께 함
  - 이 기능이 들어가는 날 **기존 병원의 대시보드 완성도가 100% → 78% 로 내려감**(새 항목 둘이 비어 있으므로 — 의도된 것, 안내 필요)
  - ⚠️ 서버 쪽 함정 하나를 계약에 못 박음: 지금 병원 저장은 시술 목록을 **통째로 바꿔 쓰는** 방식이라, 가격 칸이 생긴 뒤 그대로 두면 병원 이름만 고쳐 저장해도 **가격이 전부 지워짐** → 합쳐 쓰는 방식으로 바꿔야 함
  - **협업자에게 확인할 것**(계약 문서 §21 열린 질문): CCTV 칩을 남길지(요청서 9개에 없음), 탐색의 `진료시간` 조건(지금은 야간 상담 여부)과 새 `야간 진료` 칩의 관계, 진료시간을 시각으로 저장할지, 가격 상한, 사진 주소 형태·보관 기간, 탐색의 가격 비교표를 시술별 가격으로 바꿀지 등
