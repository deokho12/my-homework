# 알림함 (사용자용)

> 상담 상태가 바뀌었다거나 병원이 문의에 답했다는 소식을 모아서 보여주고, 읽음 처리를 하는 화면입니다.

| | |
|---|---|
| **주소** | `/notifications` |
| **누가 보나요** | 일반 사용자 (병원 관리자용 알림함은 `/admin/notifications` 에 따로 있습니다) |
| **어디서 들어오나요** | 마이페이지 메뉴의 `알림함` 줄, 넓은 화면(폭 768px 이상) 오른쪽 위 `🔔` 아이콘 — 둘 다 로그인한 상태에서만 보입니다 |
| **소스 파일** | `frontend/src/screens/notifications.tsx` |

---

## 여기서 할 수 있는 일

상태 표시: ✅ 실제로 동작함 · 🟡 화면은 되지만 데이터가 샘플 · 🚧 아직 아무 일도 안 일어남 · 🔒 로그인 필요

| 할 수 있는 일 | 상태 | 지금 어떻게 동작하나요 |
|---|---|---|
| 알림 목록 보기 | 🟡 | 사용자용 알림만 **최신순**으로 보여줍니다. 관리자용 알림은 여기 섞이지 않습니다 |
| 종류를 아이콘으로 구분하기 | ✅ | 줄 왼쪽에 종류 아이콘이 붙습니다 — 예약(달력) · 상담(클립보드) · 문의(말풍선) · 이벤트(선물) · 안내(확성기) |
| 안 읽은 알림 구분해서 보기 | ✅ | 안 읽음은 연한 브랜드색 배경 + 진한 글씨 + **제목 줄 오른쪽 끝 점**, 읽음은 흰 배경 + 흐린 글씨로 구분됩니다 (읽기 도구에서는 안 읽은 줄만 `안 읽음` 이라고 읽어줍니다) |
| 알림 하나 읽음 처리 | ✅ | 알림을 누르면 곧바로 읽음으로 바뀝니다. 새로고침해도 유지됩니다 |
| 한꺼번에 읽음 처리 | ✅ | 오른쪽 위 `모두 읽음` → 사용자용 알림 전부가 읽음으로 바뀝니다 (관리자 알림은 건드리지 않습니다) |
| 상담 상태 알림 눌러서 이동 | ✅ | 읽음 처리 후 **마이페이지 `상담 내역`** 으로 이동하고, 그 상담 줄에 포커스와 강조 테두리가 갑니다. 내 내역에 없는 상담이면 탭만 열립니다 |
| 문의 답변 알림 눌러서 이동 | ✅ | 읽음 처리 후 **마이페이지 `내 문의`** 로 이동하고, 그 문의가 **펼쳐진 채** 열립니다. 병원 상세로 보내지 않는 이유는 비공개 답변이 그곳에 없기 때문입니다 |
| 이벤트 알림 눌러서 이동 | ✅ | 읽음 처리 후 이벤트 화면(`/events`)으로 이동합니다 |
| 안내(시스템) 알림 누르기 | ✅ | 읽음 처리만 됩니다. 이동하지 않습니다 |
| 알림 하나씩 지우기 · 전체 비우기 | 🚧 | 없습니다 |
| 알림 설정 (받을 알림 고르기, 끄기) | 🚧 | 없습니다 |
| 읽은 알림만 / 안 읽은 알림만 보기 | 🚧 | 없습니다 |

## 알림이 언제 생기나요

지금 앱에서 알림을 만드는 동작은 **네 가지**입니다.

| 무엇을 하면 | 어느 알림함에 | 어떤 내용으로 |
|---|---|---|
| 사용자가 병원에 **상담을 신청하면** | 관리자 알림함 (`/admin/notifications`) | 제목 `새로운 상담 신청`, 내용 `김민준님이 상담을 신청했어요` (신청자 이름이 들어갑니다) |
| 관리자가 **상담 상태를 바꾸면** (`신규` / `연락중` / `예약확정` / `내원완료` / `취소`) | 사용자 알림함 (이 화면) | 상태마다 다른 문구 — 아래 표 |
| 관리자가 **예약 일시만 바꾸면** (예약확정 상태에서) | 사용자 알림함 (이 화면) | 제목 `예약 일시가 바뀌었어요` — 아래 표 |
| 병원이 **문의에 답변을 등록하면** | 사용자 알림함 (이 화면) | 제목 `문의에 답변이 왔어요`, 내용 `강남 스마일 치과 · 답변 앞 60자…` (문의자 이름은 들어가지 않습니다 — 받는 사람이 본인이라서입니다) |

### 상담 알림 문구 (2026-10-13)

`{병원}` 은 그 상담의 병원 이름이고, 알 수 없으면 `병원` 이라고 적습니다. `{일시}` 는
`10/9(금) 14:00` 형식입니다.

| 무슨 일이 | 제목 | 내용 |
|---|---|---|
| 예약확정 | `상담 예약이 확정됐어요` | `{병원} · {일시} 방문. 변경이 필요하면 병원에 전화해 주세요` |
| 예약 일시 변경 | `예약 일시가 바뀌었어요` | `{병원} · {일시} 방문. 변경이 필요하면 병원에 전화해 주세요` |
| 연락중 | `병원이 연락 중이에요` | `{병원}이(가) 상담 신청을 확인했어요. 곧 전화가 올 거예요` (받침에 맞춰 `이`/`가` 가 붙습니다 — `○○치과의원이`, `강남 스마일 치과가`) |
| 취소 · 연락이 안 됨 | `상담이 취소됐어요` | `{병원} · 연락이 닿지 않아 취소됐어요` |
| 취소 · 환자 요청 | `상담이 취소됐어요` | `{병원} · 요청하신 대로 취소했어요` |
| 취소 · 진료 불가 시술 | `상담이 취소됐어요` | `{병원} · 이 병원에서 진료하지 않는 시술이에요` |
| 취소 · 중복 신청 | `상담이 취소됐어요` | `{병원} · 같은 신청이 있어 하나로 정리했어요` |
| 취소 · 기타(또는 사유 없음) | `상담이 취소됐어요` | `{병원} · 자세한 사유는 병원에 문의해 주세요` |
| 내원완료 · 신규로 되돌림 | `상담 상태 변경` | `상담 상태가 '내원완료'(으)로 변경되었어요` (예전 문구 그대로입니다 — 이번 요청의 범위 밖) |

- **관리자가 고른 취소 사유 코드와 관리자용 라벨(`연락이 안 됨` 등)은 환자 화면에 그대로 나오지 않습니다.** 같은 사실을 두 독자에게 다른 문장으로 말합니다.
- **보낸 문구는 소급해 바뀌지 않습니다.** 알림을 만들 때 문장을 지어서 저장하고, 화면은 저장된 글자를 그대로 그립니다. 그래서 병원이 이름을 바꾸거나 우리가 문장을 다듬어도 **이미 간 알림은 그대로**입니다.

그 밖의 동작으로는 알림이 생기지 않습니다. **회원가입, 로그인, 찜하기, 커뮤니티 질문 등록, 병원 등록·수정, 그리고 새 문의가 들어온 것으로는 알림이 오지 않습니다** (관리자 쪽 문의 알림은 일부러 만들지 않았습니다 — 할 일 수는 [관리자 문의 화면](admin-inquiries.md)의 `미답변 N` 이 말해 줍니다).

이벤트 알림과 안내 알림은 새로 만들어지는 통로가 없고, 아래 샘플로만 존재합니다.

### 미리 들어있는 샘플 알림

**사용자 알림함 (이 화면) — 4개, 그중 1개 안 읽음**

| 종류 | 제목 | 내용 | 처음 상태 |
|---|---|---|---|
| 상담 | `상담 상태 변경` | `상담 상태가 '예약완료'(으)로 변경되었어요` | 안 읽음 |
| 상담 | `상담 상태 변경` | `상담 상태가 '연락중'(으)로 변경되었어요` | 읽음 |
| 이벤트 | `여름 이벤트 오픈` | `임플란트 무료상담 이벤트가 진행중이에요` | 읽음 |
| 안내 | `앱 업데이트 안내` | `새로운 기능이 추가되었어요` | 읽음 |

> 샘플의 `예약완료` 는 **라벨이 바뀌기 전에 나간 알림**입니다. 지금 같은 상태의 이름은 `예약확정` 이고, 이미 보낸 알림 문구는 소급해 고치지 않습니다 (보낸 그대로 남는 것이 기록입니다).

**관리자 알림함 (`/admin/notifications`) — 3개, 그중 2개 안 읽음**

| 종류 | 제목 | 내용 | 처음 상태 |
|---|---|---|---|
| 상담 | `새로운 상담 신청` | `김민준님이 상담을 신청했어요` | 안 읽음 |
| 상담 | `새로운 상담 신청` | `이서연님이 상담을 신청했어요` | 안 읽음 |
| 안내 | `정기 점검 안내` | `7/31 새벽 서버 점검이 예정되어 있어요` | 읽음 |

## 사용자용과 관리자용이 나뉘나요

**나뉩니다.** 알림 하나하나에 "누구에게 보여줄 알림인지"(`사용자` 또는 `관리자`)가 정해져 있고, 화면이 그 표시로 걸러서 보여줍니다.

| | 사용자 알림함 | 관리자 알림함 |
|---|---|---|
| 주소 | `/notifications` | `/admin/notifications` |
| 들어가는 곳 | 마이페이지 메뉴의 `알림함`, 넓은 화면 오른쪽 위 `🔔` | 관리자 홈(`/admin`) 오른쪽 위 `🔔` |
| 어떤 알림이 오나 | 상담 상태가 바뀌었을 때, 병원이 내 문의에 답했을 때 | 누가 상담을 신청했을 때 |
| 알림을 누르면 | 상담 알림은 **마이페이지 `상담 내역`** 으로, 문의 답변 알림은 **마이페이지 `내 문의`** 로 | 그 **상담 상세**(`/admin/consultations/:id`)로 |
| `모두 읽음` | 사용자 알림만 처리 | 관리자 알림만 처리 |
| 줄 모양 | 종류 아이콘 + 제목 + 내용 + 시각, 안 읽음 점은 제목 줄 오른쪽 끝 | 예전 모양 그대로 (왼쪽 점 + 제목 + 내용 + 시각) |

**두 화면은 저장 공간을 함께 쓰지만 줄 모양은 2026-10-13부터 다릅니다.** 관리자 알림함은
종류가 둘(상담 신청·안내)뿐이라 아이콘의 득이 작아 일부러 손대지 않았습니다 — 두 화면의
알림 줄은 코드도 따로입니다. 공통으로 남은 것은 저장소와 `모두 읽음` 동작입니다.

## 화면에 보이는 정보

- **`알림함`** — 화면 안쪽 제목 (헤더 제목은 `알림`)
- **`모두 읽음`** — 오른쪽 위 글자 버튼
- **알림 줄** — 하나마다
  - 왼쪽 종류 아이콘 (예약 달력 · 상담 클립보드 · 문의 말풍선 · 이벤트 선물 · 안내 확성기)
  - 제목 (예: `상담 예약이 확정됐어요`)
  - 제목 줄 오른쪽 끝 작은 점 (안 읽은 알림에만)
  - 내용 (예: `강남 스마일 치과 · 10/9(금) 14:00 방문. 변경이 필요하면 병원에 전화해 주세요`) — 길면 3줄까지 보이고, 넓은 화면에서는 2줄입니다
  - 날짜와 시간 — `10/9 14:02` (**서울 기준**입니다. 해외에서 접속해도 병원이 말한 시각과 같습니다)
- **알림이 하나도 없을 때** — 🔔 그림과 `아직 도착한 알림이 없어요`

| 어디로 | 무엇을 눌렀을 때 |
|---|---|
| 마이페이지 `상담 내역` | 상담 알림 (예약확정·연락중·취소·내원완료 전부 — 그 상담 줄이 강조됩니다) |

안내(시스템) 알림은 눌러도 이동하지 않습니다.

## 알아두실 것

- **실제 푸시 알림이 아닙니다.** 휴대폰 알림, 문자, 이메일, 카카오 알림톡으로 나가지 않습니다. 앱 안 알림함에만 쌓입니다.
- **알림이 브라우저에 저장됩니다.** 다른 컴퓨터나 시크릿 창에서 열면 그동안 쌓인 알림은 없고 샘플 4개만 보입니다. 브라우저 데이터를 지우면 읽음 처리한 내역도 함께 초기화됩니다.
- **알림이 계정별로 나뉘어 있지 않습니다.** 어떤 계정으로 로그인해도 같은 사용자 알림 목록이 보입니다. "다른 사람이 신청한 상담의 상태 변경 알림"이 내 알림함에 보이는 것은 이 때문입니다.
- **그래서 내가 관리자 화면에서 상담 상태를 직접 바꾸면, 내 알림함에도 그 상담 알림(`상담 예약이 확정됐어요` 등)이 곧바로 생깁니다.** 실제 서비스에서는 그 상담을 신청한 사람에게만 가야 하는 알림입니다.
- **알림함으로 들어가는 입구는 로그인해야 보이지만, 화면 자체는 로그인 없이도 열립니다.** 주소창에 `/notifications` 를 직접 입력하면 로그인하지 않은 상태에서도 알림 목록이 보입니다. 의도한 동작인지는 확인이 필요합니다. **(확인 필요)**
- **`🔔` 옆 빨간 숫자는 "안 읽은 사용자 알림 개수"입니다.** `모두 읽음` 을 누르거나 알림을 하나씩 눌러 읽으면 줄어들고, 0이 되면 빨간 표시가 사라집니다.
- **`모두 읽음` 은 사용자 알림만 처리합니다.** 관리자 알림함의 안 읽은 표시는 그대로 남습니다. 반대도 마찬가지입니다.
- **상담 알림을 누르면 마이페이지 `상담 내역` 이 열리고 그 상담 줄에 강조 테두리가 생깁니다.** 주소에 붙은 `consult=...` 는 한 번 쓰고 지워지므로, 새로고침하면 강조는 사라집니다. 내 내역에 없는 상담(샘플 상담, 100건 상한 밖)이면 **탭만 열리고 아무 줄도 강조되지 않습니다.**
- **알림 문구의 병원 이름은 상태를 바꾼 화면이 함께 넘겨준 값입니다.** 그 값이 없으면 문구에 `병원` 이라고 적힙니다 (틀린 이름을 적지 않습니다). 서버가 알림을 만들게 되면 병원 표에서 바로 가져옵니다.
- **2026-10-13 이전에 생긴 알림과 샘플 알림은 종류 아이콘이 `상담`(클립보드)으로 보입니다.** 그 알림들에는 "어떤 상태로 바뀐 알림인지"가 적혀 있지 않아 예약 아이콘을 붙일 근거가 없습니다. 문구도 예전 그대로입니다.
- **문의 답변 알림도 계정별로 나뉘어 있지 않습니다.** 같은 브라우저의 다른 계정으로 로그인해도 `문의에 답변이 왔어요` 가 보입니다. 그 알림을 눌러 열리는 `내 문의` 탭에는 **내 문의만** 나오므로 질문 본문은 보이지 않지만, **알림 줄에 적힌 답변 앞 60자는 그대로 읽힙니다** — 비공개로 답한 문의도 그렇습니다.
- **안내(시스템) 알림은 눌러도 아무 곳으로도 가지 않습니다.** 글씨만 흐려집니다. 고장이 아닙니다.
- **알림을 지우는 기능이 없습니다.** 한 번 생긴 알림은 계속 쌓이고, 읽음으로만 바뀝니다.
- **샘플 알림의 날짜가 2026년 6~7월로 되어 있습니다.** 최신순 정렬이라 새로 생긴 알림은 항상 이 샘플들보다 위에 놓입니다.
- 날짜와 시간은 **서울 기준**(`10/9 14:02`)으로 표시됩니다 — 보는 컴퓨터의 시간대가 아니라, 마이페이지의 `10/9(금) 14:00 방문` 과 같은 기준입니다.

## 이 화면을 바꾸고 싶을 때

`docs/features/requests/_TEMPLATE.md` 를 복사해서 `docs/features/requests/` 에 요청서를 만들거나,
채팅창에 `/feature-request` 를 입력하세요.

이 화면에서 손대면 함께 확인해야 하는 것:

- **관리자 알림함(`/admin/notifications`)과 같은 데이터**를 씁니다. 줄 모양 코드는 따로지만(2026-10-13) 읽음 처리·`모두 읽음`·저장소는 하나라, 그 셋을 바꾸면 관리자 알림함도 함께 확인해야 합니다.
- **상담 신청 화면**이 관리자 알림을, **관리자 상담 상세의 상태 변경**과 **[관리자 문의 화면](admin-inquiries.md)의 `답변 등록`** 이 사용자 알림을 만듭니다. 알림 문구를 바꾸려면 그 세 곳을 봐야 합니다. 상담 알림 문구는 **한 곳**(`frontend/src/features/consult/consultNotificationText.ts`)에서 만들어지니 문장만 고칠 때는 그 파일만 보면 됩니다.
- **상담 알림을 누르면 가는 곳**은 [마이페이지](mypage.md) `상담 내역` 입니다. 그 탭의 줄 모양·주소(`?tab=consults&consult=...`)를 바꾸면 알림의 이동도 함께 확인해야 합니다.
- **`🔔` 배지 숫자**(넓은 화면 상단 메뉴, 마이페이지 `알림함` 줄, 관리자 홈)가 모두 이 데이터의 "안 읽음 개수"를 셉니다.
- **알림을 계정별로 나누려면** 로그인한 사람과 알림을 연결하는 처리가 필요합니다. 상담 신청은 2026-10-12부터 신청한 계정을 (이 브라우저 안에서) 기억하지만, 알림 자체에는 아직 받는 사람이 없습니다.
