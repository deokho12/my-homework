# 문의하기

> 병원 한 곳에 **연락처 없이** 궁금한 점을 물어보는 화면입니다. 주제를 하나 고르고 내용을 적어 보내면 같은 화면이 완료 화면으로 바뀌고, 병원이 답하면 알림이 옵니다.

| | |
|---|---|
| **주소** | `/inquiry/:hospitalId` (예: `/inquiry/h1`) |
| **누가 보나요** | 로그인한 사용자만 |
| **어디서 들어오나요** | 병원 상세의 `문의` 섹션에 있는 `문의하기` 버튼 |
| **소스 파일** | `frontend/src/pages/InquiryPage.tsx` (폼·완료 화면은 `frontend/src/features/inquiry/components/`) |

---

## 상담 신청과 무엇이 다른가요

| | 문의하기 | [상담 신청](consult-request.md) |
|---|---|---|
| 남기는 것 | 주제 + 내용 | 이름 · 연락처 · 희망 시술 · 희망 연락 시간 |
| 연락 방법 | **앱 안에서 답변을 받습니다** (전화 없음) | 병원이 전화합니다 |
| 개인정보 동의 | **없습니다** (병원에 넘길 개인정보가 없습니다) | 제3자 제공 동의 필수 |
| 공개 | 공개를 선택하면 **병원이 공개로 답했을 때** 병원 상세에 Q/A 로 남습니다 | 공개되지 않습니다 |
| 상담 마감 병원 | 문의할 수 있습니다 | 신청 버튼이 잠깁니다 |

## 여기서 할 수 있는 일

상태 표시: ✅ 실제로 동작함 · 🟡 화면은 되지만 데이터가 샘플 · 🚧 아직 아무 일도 안 일어남 · 🔒 로그인 필요

| 할 수 있는 일 | 상태 | 지금 어떻게 동작하나요 |
|---|---|---|
| 주제 고르기 | ✅ | `가격` `진료시간` `주차·위치` `시술 방법` `기타` 다섯 개 알약 버튼. **처음에는 아무것도 골라져 있지 않고**, 고르지 않으면 보낼 수 없습니다 |
| 내용 쓰기 | ✅ | 여러 줄 입력칸. 오른쪽 아래에 글자 수(`0/1000`)가 같이 보입니다 |
| 공개 여부 고르기 | ✅ | `다른 사람도 볼 수 있게 공개` 체크박스. **기본으로 켜져 있습니다** |
| 문의 남기기 | ✅ 🔒 | 주제와 내용이 채워졌을 때만 눌립니다. 누르면 같은 주소에서 **완료 화면**으로 바뀌고, 병원 관리자의 `문의` 화면 `미답변` 탭 맨 위에 나타납니다 |
| 완료 화면에서 `내 문의 보기` | ✅ | 마이페이지의 `내 문의` 탭으로 이동합니다 (뒤로 가기로 방금 보낸 폼에 돌아오지 않도록 화면을 바꿔치기합니다) |
| 안내 문구의 `상담 신청` 누르기 | ✅ | 같은 병원의 상담 신청 화면으로 바꿔 이동합니다 |
| 뒤로 가기 | ✅ | 화면 위쪽 `‹` 화살표 |

## 화면에 보이는 정보

- **화면 제목** — 위쪽 헤더에 `문의하기`
- **병원 이름** — `○○치과에 문의` + 아래에 `지역 · 주소`
- **안내 박스** — `연락처 없이 앱 안에서 답변을 받아요. 예약까지 원하시면 상담 신청이 더 빨라요.`
- **주제 칩 5개** — `무엇이 궁금하세요?`
- **내용 입력칸** — `예) 인레이 금과 세라믹 차이가 궁금해요`
- **공개 체크박스** — `병원이 답변하고 공개에 동의하면 병원 상세의 '문의'에 질문과 답변이 남아요. 이름은 보이지 않아요.`
- **`문의 남기기` 버튼** — 조건을 채우기 전에는 흐리게 보이고, 그때는 아래에 `주제를 고르고 내용을 5자 이상 적으면 보낼 수 있어요` 한 줄이 보입니다

### 입력 칸별로 지금 무엇을 검사하나요

| 입력 칸 | 필수인가요 | 지금 실제로 검사하는 것 | 검사하지 않는 것 |
|---|---|---|---|
| 주제 | 필수 | 다섯 개 중 하나를 골랐는지 (기본값 없음) | — |
| 내용 | 필수 | 앞뒤 공백을 뺀 뒤 **5자 이상 1000자 이하** | 내용의 성격 (욕설·광고·개인정보를 거르지 않습니다) |
| 공개 여부 | — | 켜짐/꺼짐 둘 중 하나 (기본 켜짐) | — |

주제를 고르지 않은 것은 **빨간 오류로 말하지 않습니다.** 아직 하지 않은 일을 틀렸다고 하지 않기 위해, 버튼만 흐려지고 아래 한 줄이 이유를 말합니다. 내용 길이 오류(`문의 내용을 5자 이상 입력해주세요` · `문의 내용은 1000자까지 쓸 수 있어요`)는 그 칸을 한 번 벗어난 뒤에 보입니다. 이 문장은 **서버가 같은 입력을 거절할 때 쓰는 문장과 같습니다** — 서버가 생겨도 같은 말이 보입니다.

### 특별한 상황일 때

| 상황 | 화면 |
|---|---|
| 로그인하지 않고 이 주소로 들어옴 | 자동으로 로그인 화면으로 보냅니다. 로그인하면 이 화면으로 돌아옵니다 |
| 없는 병원 주소로 들어옴 | `병원 정보를 찾을 수 없어요` |
| 보내기에 실패함 | 브라우저 알림창으로 `문의를 남기지 못했어요` + 이유가 뜨고, **쓴 내용은 그대로 남습니다** |
| 보내기에 성공함 | 같은 주소에서 폼이 사라지고 `문의를 남겼어요` 가 나옵니다. 병원 / 주제 / 공개 여부(`공개 요청함` 또는 `비공개`)가 요약으로 보입니다 |
| 완료 후 뒤로 가기 | 직전 화면(보통 병원 상세)으로 갑니다. 다시 들어오면 빈 폼입니다 |

## 알아두실 것

- **문의를 남겨도 실제로 병원에 전달되지 않습니다.** 서버가 없어서 내용은 이 브라우저 안에만 저장됩니다. 다른 컴퓨터나 시크릿 창에서는 보이지 않고, 브라우저 데이터를 지우면 함께 사라집니다.
- **공개로 남겨도 바로 공개되지 않습니다.** 병원이 **답변하면서 공개를 허용**해야 병원 상세의 `문의` 섹션에 올라갑니다. 셋 중 하나라도 아니면(내가 비공개 / 병원이 비공개 / 아직 미답변) 그곳에 보이지 않습니다.
- **공개된 Q/A 에는 작성자 이름이 아예 보이지 않습니다.** 닉네임도 없습니다. 병원 관리자에게만 `김*준` 처럼 가운데를 가린 이름이 보입니다.
- **문의에는 이름·전화번호를 받지 않습니다.** 그래서 개인정보 제3자 제공 동의도 없습니다. 다만 **내용에 전화번호를 직접 적으면 그대로 저장되고 병원에 보입니다** — 앱이 걸러주지 않습니다.
- **같은 병원에 몇 번이든 문의할 수 있습니다.** 도배를 막는 규칙이 아직 없습니다 (버튼 연타로 두 건이 들어가는 것은 막습니다).
- **보낸 문의는 고치거나 지울 수 없습니다.** 취소·삭제 화면이 없습니다.
- **병원이 답하면 알림함에 `문의에 답변이 왔어요` 가 쌓입니다.** 누르면 마이페이지 `내 문의` 의 그 문의가 펼쳐진 채 열립니다. 다만 **지금은 알림에 받는 사람 구분이 없어서, 같은 브라우저의 다른 계정으로 로그인해도 그 알림이 보입니다** — 알림 줄에 답변 앞 60자가 적혀 있어 그만큼은 그 계정에게도 읽힙니다 ([known-issues.md](known-issues.md)).
- **상담 마감인 병원에도 문의할 수 있습니다.** 문의는 예약 창구가 아닙니다.

## 이 화면을 바꾸고 싶을 때

`docs/features/requests/_TEMPLATE.md` 를 복사해서 `docs/features/requests/` 에 요청서를 만들거나,
채팅창에 `/feature-request` 를 입력하세요.

이 화면에서 손대면 함께 확인해야 하는 것:

- 여기서 남긴 문의는 **병원 관리자 `문의` 화면([admin-inquiries.md](admin-inquiries.md))과 같은 데이터**입니다. 저장 항목을 늘리면 그 화면도 함께 손봐야 합니다.
- **공개 판정은 한 곳에만 있습니다** (`frontend/src/features/inquiry/inquiryVisibility.ts`). 병원 상세의 공개 Q/A, 관리자 상세의 `공개/비공개` 표기, 공개 건수가 전부 이 함수를 씁니다. 한쪽만 고치면 비공개 문의가 공개 목록에 뜰 수 있습니다.
- **주제 다섯 개와 글자 수 5~1000 은 서버 계약(`docs/api/openapi.yaml` 의 `InquiryTopic` · `HospitalInquiryCreateRequest`)과 같은 값이어야 합니다.**
- 병원 상세의 `문의하기` 버튼, 마이페이지 `내 문의` 탭, 알림함의 답변 알림이 이 화면과 한 줄로 이어집니다.
