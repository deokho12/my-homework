# 회원가입

> 이름·이메일·비밀번호를 입력해 새 계정을 만드는 화면입니다. 가입이 끝나면 곧바로 로그인 상태가 됩니다.

| | |
|---|---|
| **주소** | `/auth/signup` (돌아갈 화면이 있을 때는 `/auth/signup?redirect=/consult/h1` 처럼 주소 뒤에 붙습니다) |
| **누가 보나요** | 아직 계정이 없는 사용자 |
| **어디서 들어오나요** | 로그인 화면의 `아직 계정이 없으신가요? 회원가입`, 마이페이지의 `회원가입` 버튼 |
| **소스 파일** | `frontend/src/screens/auth/signup.tsx` (화면) + `frontend/src/store/useAuthStore.ts` (계정 저장) |

| 할 수 있는 일 | 상태 | 지금 어떻게 동작하나요 |
|---|---|---|
| 이름 입력 | ✅ | 자유롭게 입력합니다. 앞뒤 공백은 저장할 때 지워집니다 |
| 이메일 입력 | ✅ | 자유롭게 입력합니다. 형식은 검사하지 않습니다 |
| 비밀번호 입력 | ✅ | 점(●)으로 가려집니다. 6자 이상이어야 합니다 |
| 비밀번호 확인 입력 | ✅ | 점(●)으로 가려집니다. 위 비밀번호와 같아야 합니다 |
| 가입하기 | ✅ | 이미 가입된 이메일이 아니면 계정을 만들고 **곧바로 로그인 상태가 됩니다**. 별도의 "가입 완료" 안내 화면이나 알림창은 없고, 바로 이전 화면(또는 가입 전에 하려던 화면)으로 넘어갑니다 |

## 화면에 보이는 정보

- **화면 제목** — 헤더에 `회원가입`, 본문에도 큰 글씨로 `회원가입`
- **안내 문구** — `몰라몰라에서 나에게 맞는 병원을 찾아보세요`
- **입력 칸 4개** — 이름 / 이메일 / 비밀번호 / 비밀번호 확인
- **빨간 오류 문구** — 문제가 있을 때만, `비밀번호 확인` 칸과 `가입하기` 버튼 사이에 한 줄로 나타납니다
- **`가입하기` 버튼** — 조건을 채우기 전에는 흐리게 보이고 눌리지 않습니다

### 입력 칸별로 지금 무엇을 검사하나요

| 입력 칸 | 안내 문구(placeholder) | 지금 실제로 검사하는 것 | 검사하지 않는 것 |
|---|---|---|---|
| 이름 | `이름을 입력해주세요` | 앞뒤 공백을 뺀 뒤 한 글자 이상인지 | 글자 수 제한, 한글/영문 여부, 특수문자·숫자 사용 여부 |
| 이메일 | `example@email.com` | 앞뒤 공백을 뺀 뒤 한 글자 이상인지 + **이미 가입된 이메일인지** | **이메일 형식을 검사하지 않습니다.** `@` 가 없어도, `abc` 여도 가입됩니다. 실제로 존재하는 메일 주소인지 확인하는 인증 메일도 없습니다 |
| 비밀번호 | `6자 이상 입력해주세요` | **6자 이상인지** | 영문·숫자·특수문자 조합 같은 복잡도 규칙이 없습니다. `aaaaaa`, `123456`, 공백 6칸도 통과합니다 |
| 비밀번호 확인 | `비밀번호를 다시 입력해주세요` | 한 글자 이상인지 + **위 비밀번호와 정확히 같은지** | — |

**`가입하기` 버튼이 켜지는 조건**: 이름이 공백이 아니고 + 이메일이 공백이 아니고 + 비밀번호가 6자 이상이고 + 비밀번호 확인에 한 글자 이상 있을 때. 두 비밀번호가 같은지는 **버튼을 누른 뒤에** 확인합니다.

### 가입에 실패했을 때

| 상황 | 나오는 문구 |
|---|---|
| 비밀번호 확인이 비밀번호와 다름 | `비밀번호가 일치하지 않아요` |
| 이미 그 이메일로 가입한 계정이 있음 | `이미 가입된 이메일이에요` |
| 비밀번호가 6자 미만 | `비밀번호는 6자 이상이어야 해요` — 다만 6자 미만이면 버튼 자체가 눌리지 않으므로 **이 문구는 실제로는 거의 보이지 않습니다** |

- 이 문구들은 문제가 된 입력 칸 아래가 아니라 **`가입하기` 버튼 바로 위**에 한 줄로 나옵니다. 예를 들어 `이미 가입된 이메일이에요` 도 이메일 칸이 아니라 맨 아래에 뜹니다.
- 어느 칸이든 한 글자라도 고치면 문구가 즉시 사라집니다.

### 저장될 때 다듬어지는 값

- **이메일** — 앞뒤 공백을 지우고 **모두 소문자로 바꿔서** 저장합니다. 그래서 `Hong@Test.com` 으로 가입한 뒤 `hong@test.com` 으로 로그인해도 같은 계정입니다. 반대로 대문자만 다른 이메일로 다시 가입하려 하면 `이미 가입된 이메일이에요` 가 나옵니다.
- **이름** — 앞뒤 공백을 지워서 저장합니다.
- **비밀번호** — 입력한 그대로 저장·비교합니다 (공백·대소문자 모두 구분).

## 이 화면에서 이동할 수 있는 곳

| 어디로 | 무엇을 눌렀을 때 |
|---|---|
| 가입 전에 하려던 화면 (예: 상담 신청) | `가입하기` 성공 — 로그인 화면을 거쳐 들어온 경우 그 화면으로 바로 이어집니다 |
| 직전 화면 | `가입하기` 성공 (돌아갈 화면 정보가 없을 때), 또는 헤더의 `‹` |

이 화면에는 로그인 화면으로 되돌아가는 링크가 없습니다. 뒤로 가기를 쓰면 됩니다.

## 알아두실 것

- **서버가 없어서 브라우저 안에서만 동작합니다.** 가입한 계정은 **가입한 그 브라우저에만 저장됩니다.** 다른 컴퓨터, 다른 브라우저, 시크릿 창에서는 그 계정으로 로그인할 수 없습니다. 브라우저 데이터를 지우면 계정도 사라집니다.
- **비밀번호가 브라우저에 그대로 저장됩니다.** 암호화하지 않은 임시 구현이라 실제 서비스로 쓸 수 없습니다. **평소 쓰시는 실제 비밀번호는 절대 입력하지 마세요.**
- **이메일 인증이 없습니다.** 아무 문자열이나 넣어도 가입되고, 확인 메일도 가지 않습니다.
- **약관 동의 절차가 없습니다.** `서비스 이용약관`·`개인정보 처리방침`·`위치기반 서비스 이용약관` 화면은 앱에 따로 있지만, 회원가입 과정에는 연결되어 있지 않습니다.
- **휴대폰 번호 입력·본인 인증이 없습니다.** 가입 시 받는 정보는 이름·이메일·비밀번호 세 가지뿐입니다.
- **비밀번호 규칙은 "6자 이상" 하나뿐입니다.** 조합 규칙도, 최대 길이 제한도 없습니다.
- **가입 완료 안내가 따로 없습니다.** 버튼을 누르면 곧바로 로그인된 상태로 화면이 바뀌기 때문에, "정말 가입된 건가?" 하고 오해할 수 있습니다. 마이페이지에 `{이름}님, 안녕하세요` 가 보이면 가입·로그인이 된 것입니다.
- **오류 안내가 문제가 된 칸 아래가 아니라 버튼 위에 나옵니다.**
- **입력 칸에서 Enter 를 눌러도 가입되지 않습니다.** `가입하기` 버튼을 눌러야 합니다.
- 주소를 직접 입력해 이 화면에 들어온 뒤 가입하면, 돌아갈 직전 화면이 없어 브라우저가 이전 페이지(사이트 밖)로 나갈 수 있습니다. **(확인 필요 — 실제 브라우저에서 확인하지 못했습니다)**

## 이 화면을 바꾸고 싶을 때

`docs/features/requests/_TEMPLATE.md` 를 복사해서 `docs/features/requests/` 에 요청서를 만들거나,
채팅창에 `/feature-request` 를 입력하세요.

이 화면에서 손대면 함께 확인해야 하는 것:

- **로그인 화면과 같은 계정 저장소**를 씁니다. 이메일을 다듬는 방식(공백 제거·소문자 변환)이나 비밀번호 규칙을 한쪽만 바꾸면, 가입은 되는데 로그인이 안 되는 상태가 됩니다.
- **가입하면 곧바로 로그인 상태가 됩니다.** 찜하기·상담 신청·마이페이지 표시가 함께 영향을 받습니다.
- **입력 항목을 늘리려면**(휴대폰 번호, 약관 동의 등) 계정에 저장하는 정보의 모양도 함께 바꿔야 합니다.
- 가입 후 돌아가는 화면은 **로그인 화면이 넘겨준 주소**를 그대로 따릅니다.
