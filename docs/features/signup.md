# 회원가입

> 이름·이메일·비밀번호를 입력해 새 계정을 만드는 화면입니다. 가입이 끝나면 곧바로 로그인 상태가 됩니다.

| | |
|---|---|
| **주소** | `/auth/signup` (돌아갈 화면이 있을 때는 `/auth/signup?redirect=/consult/h1` 처럼 주소 뒤에 붙습니다) |
| **누가 보나요** | 아직 계정이 없는 사용자 |
| **어디서 들어오나요** | 로그인 화면의 `아직 계정이 없으신가요? 회원가입`, 마이페이지의 `회원가입` 버튼 |
| **소스 파일** | `frontend/src/screens/auth/signup.tsx` (화면) + `frontend/src/features/auth/schemas/authSchemas.ts` (입력 검사) + `frontend/src/store/useAuthStore.ts` (로그인 상태) — 계정은 **서버**에 만들어집니다 |

## 여기서 할 수 있는 일

상태 표시: ✅ 실제로 동작함 · 🟡 화면은 되지만 데이터가 샘플 · 🚧 아직 아무 일도 안 일어남 · 🔒 로그인 필요

| 할 수 있는 일 | 상태 | 지금 어떻게 동작하나요 |
|---|---|---|
| 이름 입력 | ✅ | 자유롭게 입력합니다. 앞뒤 공백은 저장할 때 지워집니다 |
| 이메일 입력 | ✅ | `가입하기` 를 누를 때 이메일 형식인지 검사합니다 |
| 비밀번호 입력 | ✅ | 점(●)으로 가려집니다. 6자 이상이어야 합니다 |
| 비밀번호 확인 입력 | ✅ | 점(●)으로 가려집니다. 위 비밀번호와 같아야 합니다 |
| 약관 동의 | ✅ | `(필수) 서비스 이용약관에 동의합니다` 처럼 세 가지(서비스 이용약관·개인정보 처리방침·위치기반 서비스 이용약관)에 **모두 체크해야** 가입됩니다. 각 줄의 `보기` 는 해당 약관 화면으로 가지만, **그 화면은 아직 `준비중입니다` 만 보입니다** |
| 가입하기 | ✅ | **서버에** 계정을 만들고 **곧바로 로그인 상태가 됩니다**. 별도의 "가입 완료" 안내 화면이나 알림창은 없고, 바로 이전 화면(또는 가입 전에 하려던 화면)으로 넘어갑니다 |
| 뒤로 가기 | ✅ | 화면 위쪽 `‹` 화살표 |

이 화면에는 **구글·카카오 간편 가입 버튼이 없습니다.** (로그인 화면에만 있고, 그쪽도 아직 준비중입니다)

## 화면에 보이는 정보

- **화면 제목** — 헤더에 `회원가입`, 본문에도 큰 글씨로 `회원가입`
- **안내 문구** — `몰라몰라에서 나에게 맞는 병원을 찾아보세요`
- **입력 칸 4개** — 이름 / 이메일 / 비밀번호 / 비밀번호 확인
- **`약관 동의` 묶음** — 필수 체크 3개, 각각 `보기` 링크
- **빨간 오류 문구** — 입력이 잘못되면 **그 칸(또는 그 약관 줄) 바로 아래**에, 어느 칸의 문제도 아니면 `가입하기` 버튼 바로 위에 한 줄로
- **`가입하기` 버튼** — 언제나 누를 수 있습니다. 누르는 순간 검사하고 문제가 있는 칸을 알려 줍니다. 서버에 만드는 동안에는 `가입 중` 으로 바뀌고 흐려집니다

### 입력 칸별로 지금 무엇을 검사하나요

| 입력 칸 | 안내 문구(placeholder) | 지금 실제로 검사하는 것 | 검사하지 않는 것 |
|---|---|---|---|
| 이름 | `이름을 입력해주세요` | 앞뒤 공백을 뺀 뒤 한 글자 이상인지, 50자 이하인지 | 한글/영문 여부, 특수문자·숫자 사용 여부 |
| 이메일 | `example@email.com` | 비어 있지 않은지, **이메일 형식인지**(`이메일 형식이 올바르지 않아요`), 254자 이하인지 + (서버가) **이미 가입된 이메일인지** | 실제로 존재하는 메일 주소인지 확인하는 인증 메일은 없습니다 |
| 비밀번호 | `6자 이상 입력해주세요` | **6자 이상 128자 이하인지** | 영문·숫자·특수문자 조합 같은 복잡도 규칙이 없습니다. `aaaaaa`, `123456` 도 통과합니다 |
| 비밀번호 확인 | `비밀번호를 다시 입력해주세요` | 비어 있지 않은지 + **위 비밀번호와 정확히 같은지** | — |
| 약관 3개 | — | 셋 다 체크했는지 (빠진 줄 아래에 `동의가 필요해요`) | — |

검사는 **`가입하기` 를 누를 때** 합니다. 한 번 누른 뒤에는 칸을 고치는 대로 다시 검사해서, 고쳐지면 칸 아래 문구가 사라집니다.

### 가입에 실패했을 때

| 상황 | 나오는 문구 |
|---|---|
| 비밀번호 확인이 비밀번호와 다름 | `비밀번호가 일치하지 않아요` (비밀번호 확인 칸 아래) |
| 비밀번호가 6자 미만 | `비밀번호는 6자 이상이어야 해요` (비밀번호 칸 아래) |
| 약관에 체크하지 않음 | `동의가 필요해요` (그 약관 줄 아래) |
| 이미 그 이메일로 가입한 계정이 있음 | `이미 가입된 이메일이에요` (**`가입하기` 버튼 바로 위** — 서버가 알려 주는 문제라서) |
| 짧은 시간에 너무 여러 번 시도함 | `요청이 너무 많아요. 잠시 후 다시 시도해주세요` (버튼 위) |

- 칸 아래 문구는 칸을 고치는 대로 다시 검사되어 사라지고, 버튼 위 문구는 다시 `가입하기` 를 누를 때 지워집니다.

### 저장될 때 다듬어지는 값

- **이메일** — 서버가 앞뒤 공백을 지우고 **모두 소문자로 바꿔서** 저장합니다. 그래서 `Hong@Test.com` 으로 가입한 뒤 `hong@test.com` 으로 로그인해도 같은 계정입니다. 반대로 대문자만 다른 이메일로 다시 가입하려 하면 `이미 가입된 이메일이에요` 가 나옵니다.
- **이름** — 앞뒤 공백을 지워서 저장합니다.
- **비밀번호** — 서버가 **암호화(복원할 수 없는 형태)** 해서 보관합니다. 로그인할 때는 입력한 그대로 비교합니다 (공백·대소문자 모두 구분).

## 이 화면에서 이동할 수 있는 곳

| 어디로 | 무엇을 눌렀을 때 |
|---|---|
| 가입 전에 하려던 화면 (예: 상담 신청) | `가입하기` 성공 — 로그인 화면을 거쳐 들어온 경우 그 화면으로 바로 이어집니다 |
| 직전 화면 | `가입하기` 성공 (돌아갈 화면 정보가 없을 때), 또는 헤더의 `‹` |

이 화면에는 로그인 화면으로 되돌아가는 링크가 없습니다. 뒤로 가기를 쓰면 됩니다.

## 알아두실 것

- **계정은 실제 서버에 만들어집니다.** 다른 컴퓨터·브라우저·시크릿 창에서도 그 계정으로 로그인할 수 있고, 비밀번호는 서버가 암호화해 보관합니다. 다만 **지금 서버는 개발용**이라, 개발 서버를 다시 만들면 거기서 가입한 계정도 사라질 수 있습니다 **(확인 필요 — 개발 서버를 초기화하는 절차는 개발 쪽에 확인)**.
- **이메일 인증이 없습니다.** 아무 문자열이나 넣어도 가입되고, 확인 메일도 가지 않습니다.
- **약관 세 가지에 동의해야 가입됩니다.** 다만 약관 화면(`보기`)은 아직 `준비중입니다` 만 보여서, **사용자가 읽을 수 있는 약관 본문이 없는 채로 동의를 받고 있습니다.** 실제 서비스 전에 약관 본문이 들어가야 합니다.
- **휴대폰 번호 입력·본인 인증이 없습니다.** 가입 시 받는 정보는 이름·이메일·비밀번호 세 가지뿐입니다.
- **비밀번호 규칙은 "6자 이상 128자 이하" 뿐입니다.** 조합 규칙은 없습니다.
- **가입 완료 안내가 따로 없습니다.** 버튼을 누르면 곧바로 로그인된 상태로 화면이 바뀌기 때문에, "정말 가입된 건가?" 하고 오해할 수 있습니다. 마이페이지에 `{이름}님, 안녕하세요` 가 보이면 가입·로그인이 된 것입니다.
- **입력 칸에서 Enter 를 누르면 `가입하기` 를 누른 것과 같습니다.**
- 주소를 직접 입력해 이 화면에 들어온 뒤 가입하면, 돌아갈 직전 화면이 없어 브라우저가 이전 페이지(사이트 밖)로 나갈 수 있습니다. **(확인 필요 — 실제 브라우저에서 확인하지 못했습니다)**

## 이 화면을 바꾸고 싶을 때

`docs/features/requests/_TEMPLATE.md` 를 복사해서 `docs/features/requests/` 에 요청서를 만들거나,
채팅창에 `/feature-request` 를 입력하세요.

이 화면에서 손대면 함께 확인해야 하는 것:

- **로그인 화면과 같은 계정 저장소**를 씁니다. 이메일을 다듬는 방식(공백 제거·소문자 변환)이나 비밀번호 규칙을 한쪽만 바꾸면, 가입은 되는데 로그인이 안 되는 상태가 됩니다.
- **가입하면 곧바로 로그인 상태가 됩니다.** 찜하기·상담 신청·마이페이지 표시가 함께 영향을 받습니다.
- **입력 항목을 늘리려면**(휴대폰 번호, 약관 동의 등) 계정에 저장하는 정보의 모양도 함께 바꿔야 합니다.
- 가입 후 돌아가는 화면은 **로그인 화면이 넘겨준 주소**를 그대로 따릅니다.
