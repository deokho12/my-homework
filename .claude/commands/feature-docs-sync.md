`docs/features/` 의 화면 기능 문서를 실제 코드와 맞춘다. 대상: $ARGUMENTS (비어 있으면 전체)

이 문서는 비개발자가 읽고 요청을 내는 근거다. **문서가 거짓이면 비개발자는 그걸 확인할 방법이 없다.** 그래서 코드가 바뀌면 문서도 따라와야 한다.

## 1. 대상을 정한다

`$ARGUMENTS` 에 화면 이름이 있으면 그 문서만. 비어 있으면 `docs/features/*.md` 전체 (`_TEMPLATE.md`, `README.md` 제외).

전체 점검이라면 먼저 **마지막으로 문서를 갱신한 이후 바뀐 소스 파일**을 좁혀서 시작한다:

```bash
git log --oneline -20 -- frontend/src
```

## 2. 문서와 코드를 대조한다

각 문서에 대해 명시된 소스 파일을 읽고 아래를 확인한다.

| 확인 항목 | 어긋남의 예 |
|---|---|
| **주소** | `ROUTES`(`frontend/src/App.tsx`) 의 `path` 와 다름 |
| **소스 파일 경로** | 리팩터링으로 `screens/` → `pages/` 로 옮겨졌는데 문서가 옛 경로를 가리킴 |
| **기능 표의 항목** | 코드에 있는 버튼·입력이 표에 없음, 또는 표에 있는데 코드에서 사라짐 |
| **상태 표시** | 🚧 로 적혀 있는데 실제로 구현됨. 🟡 인데 실제 데이터로 바뀜. 🔒 인데 로그인 검사가 없음 (또는 반대) |
| **화면 문구** | 백틱으로 인용된 한글 문구가 코드의 실제 문구와 다름 |
| **이동할 수 있는 곳** | 라우팅이 바뀜 |
| **알아두실 것** | 이미 해결된 제약이 남아 있음, 새로 생긴 제약이 빠져 있음 |

상태 판정 기준:

- ✅ 실제로 동작하고 저장까지 됨
- 🟡 화면은 되지만 `frontend/src/mocks/` 의 샘플 데이터를 씀
- 🚧 버튼·영역은 있는데 핸들러가 없거나 빈 함수
- 🔒 `useRequireAuth` / `useAuthStore` / `RequireAuth` / `RequireAdmin` 으로 막혀 있음

## 3. 문서에 없는 화면을 찾는다

`frontend/src/pages/` 와 `frontend/src/screens/` 의 화면 파일 목록을 `docs/features/` 와 대조한다. 문서가 없는 화면이 있으면 `_TEMPLATE.md` 를 기준으로 새로 만들고, `README.md` 목록에도 추가한다.

반대로 소스가 사라진 화면의 문서가 남아 있으면 지운다.

## 4. 고친다

- 어긋난 곳을 실제 코드에 맞게 수정한다
- **확인하지 못한 것은 추측으로 채우지 않는다.** `(확인 필요)` 를 붙인다
- 어투와 구조는 기존 문서를 따른다. 비개발자 독자이므로 개발 용어를 쓰지 않는다
- `README.md` 의 화면 목록과 진행 상황 표도 함께 갱신한다

## 5. 보고한다

- 문서별로 무엇이 어긋나 있었고 어떻게 고쳤는지
- 새로 만든 문서 / 지운 문서
- `(확인 필요)` 로 남긴 항목과 이유
- **문서와 코드가 어긋나 있었다는 사실 자체가 문제인 지점** — 예를 들어 🚧 로 적혀 있던 기능이 실제로는 동작하고 있었다면, 비개발자가 "이거 안 되네요"라고 잘못 판단하고 있었을 수 있다

## 하지 말 것

- 소스 코드를 고치지 않는다. 이 커맨드는 문서만 다룬다. 코드 쪽 문제를 발견하면 보고만 한다
- 문서를 예쁘게 만들려고 없는 기능을 채우지 않는다
